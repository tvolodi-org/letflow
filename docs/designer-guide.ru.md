# Руководство дизайнера: редактор бизнес-процессов

Для тех, кто проектирует бизнес-процессы и не программирует. Здесь описано то, что есть в `main` сегодня.
То, что ещё не сделано, помечено «пока недоступно». Другие языки: [English](designer-guide.md),
[Қазақша](designer-guide.kk.md). У трёх файлов одинаковые разделы и одинаковые якоря.

**Жирным** выделены названия кнопок, вкладок и полей так, как их показывает продукт на русском языке.
HTML-комментарий под каждым заголовком перечисляет ключи сообщений, которые docs-тест сверяет с файлами
сообщений продукта (`web/src/i18n/processDiagramMessages.ts`, `web/src/pages/definitions/definitionsMessages.ts`).
Ключи начинаются с `pd.` (сообщения схемы процесса) или `defs.` (сообщения списка определений).
Тексты ошибок проверки приходят с сервера на английском языке; в разделе 7 они приведены как есть.

<a id="sec-what-is-a-process"></a>
## 1. Что такое определение процесса и что такое запуск
<!-- labels: defs.title -->

**Определение процесса** — это описание бизнес-процесса: его шаги, стрелки между ними, кто выполняет каждый шаг
человека и какие значения идут вместе с процессом. Определения находятся в разделе **Бизнес-процессы**.
У определения есть версии. Одновременно **активна** только одна версия; остальные — «Черновик», «Устарело»
или «В архиве».

**Запуск** (в продукте также «экземпляр») — это один реальный проход по процессу, например одна регистрация
арендатора. Запуск всегда идёт по той версии, которая была активна при его старте. Изменение определения
никогда не меняет уже идущий запуск.

<a id="sec-steps-and-editor"></a>
## 2. Вкладки «Шаги» и «Редактор»
<!-- labels: pd.view.diagram, pd.view.editor, pd.mode.steps, pd.view.edit, pd.view.versions -->

Откройте процесс из списка (**Открыть процесс**). Вверху страницы есть переключатель с кнопками **Схема**,
**Версии**, **Править схему** и **Редактор**. Какие из них вы видите, зависит от ваших прав.

* **Схема** — картинка процесса только для чтения. Второй переключатель «Показать как» показывает тот же процесс
  либо картинкой, либо списком **Шаги**. Нажмите на шаг, чтобы увидеть сведения о нём (тип, роль, функция, шаблон).
* **Править схему** — правка прямо на картинке: добавить шаги, провести стрелки, изменить свойства шага.
* **Редактор** — полный редактор с палитрой шагов, панелью свойств, строкой проверки и исходным определением.
  Формы, записи модуля, интерфейс и адрес шага правятся только здесь.
* **Версии** — сравнение двух версий на одной схеме (только просмотр).

Если в одном из двух режимов правки есть несохранённые изменения, другой отключён, пока вы не сохраните
или не отмените их.

<a id="sec-add-edit-step"></a>
## 3. Добавить и изменить шаг
<!-- labels: pd.edit.addType, pd.edit.add, pd.edit.panel.node, pd.edit.field.label, pd.edit.connectGo, pd.edit.deleteStep, pd.edit.undo, pd.edit.redo -->

1. Откройте **Править схему**.
2. Выберите вид в поле **Тип шага** (Начало, Конец, Задача пользователя, Сервисная задача, Решение,
   Параллельно, Таймер, Подпроцесс) и нажмите **Добавить шаг**.
3. Нажмите на новый шаг. Откроется панель **Свойства шага**. Дайте шагу имя в поле **Название**. Задаче
   пользователя нужна ещё **Роль**; таймеру — **Длительность (ISO 8601)**, например `PT1H` — один час.
4. Чтобы соединить два шага, протяните стрелку от одного к другому или выберите цель в поле «Соединить этот шаг с»
   и нажмите **Соединить**. Стрелке, выходящей из **Решения**, нужно **Условие** или «Маршрут по умолчанию».
5. **Удалить шаг** убирает шаг вместе со стрелками. **Отменить** и **Повторить** возвращают и повторяют правку.

Некоторые действия продукт отклоняет сразу коротким сообщением, например «Шаг нельзя соединить с самим собой.»,
«Эти шаги уже соединены.», «В начало нельзя провести связь.», «Из конца нельзя провести связь.».
Ничего не сохраняется, пока вы не сохраните (раздел 8).

<a id="sec-function-picker"></a>
## 4. Выбор функции и типизированное сопоставление аргументов
<!-- labels: pd.edit.platform.function, pd.edit.platform.functionPlaceholder, pd.edit.platform.arguments, pd.edit.platform.source, pd.edit.platform.source.var, pd.edit.platform.source.const, pd.edit.platform.outputs, pd.edit.platform.useFunction, pd.edit.platform.useScript -->

**Сервисная задача** работает без человека. Она может вызвать **платформенную функцию** из каталога функций.

1. Выберите сервисную задачу и нажмите **Использовать платформенную функцию**.
2. Откройте поле **Функция** и выберите из списка (**Выберите функцию**). Каталог задаёт платформа;
   функцию, которой в нём нет, вручную ввести нельзя.
3. В блоке **Аргументы** у каждого аргумента есть тип, и он помечен «обязательный» или «необязательный».
   Для каждого выберите **Значение из**:
   * **Переменная процесса** — укажите имя переменной (не пустое, без точки и не имя системы);
   * **Фиксированное значение** — введите значение; оно должно подходить к типу аргумента (число, true или false
     либо корректный JSON).
4. Блок **Значения, записываемые в процесс** перечисляет, что функция добавляет в процесс.

*Типизированное сопоставление* означает: у каждого аргумента объявлен тип, и продукт проверяет, что подключённое
значение ему подходит. Отказ выглядит так: поле краснеет с коротким текстом, например «Значение должно быть числом.»
или «Имя переменной: не пустое, без точки и не имя системы.», либо у шага появляется «Два аргумента разных типов
читают одну переменную; этот шаг нельзя активировать.». Исправьте сопоставление, и красный текст исчезнет.

Функция, которая что-то записывает, берёт аргументы из формы запуска или из предыдущих шагов, но не из переменной,
которую позже заполняет человек.

**Использовать скрипт** убирает функцию и позволяет указать скрипт. У шага не может быть одновременно функции
и скрипта.

<a id="sec-notification-step"></a>
## 5. Шаг уведомления
<!-- labels: pd.edit.notify.useNotification, pd.edit.notify.channel, pd.edit.notify.channel.email, pd.edit.notify.channel.file, pd.edit.notify.template, pd.edit.notify.recipient, pd.edit.notify.values, pd.edit.notify.problem.template_missing, pd.edit.notify.problem.recipient_missing -->

Сервисная задача может отправить уведомление вместо вызова функции. Нажмите **Отправить уведомление** и заполните:

* **Канал** — **Электронная почта** или **Файл**. Для файла нужно ещё «Имя файла»: простое имя, не путь.
* **Шаблон** — выберите из зарегистрированных шаблонов («Выберите шаблон»). Шаблоны здесь не пишутся.
* **Переменная получателя** — имя переменной процесса, в которой лежит адрес. Постоянный адрес в определении
  не хранится.
* **Значения** — что получает каждая подстановка шаблона: переменную процесса или фиксированное значение.

Если чего-то не хватает, редактор говорит, например: «Выберите шаблон уведомления.» или
«Укажите переменную, из которой берётся адрес.».

**Список разрешённых исходящих адресов.** Процесс может обращаться за пределы компании только к тем адресатам,
которые компания разрешила. Список **по умолчанию пуст** (по умолчанию запрещено): пока адресат не добавлен,
уведомление на этот почтовый домен отклоняется. Добавлять адресатов может только тот, у кого есть право
«управлять исходящими адресатами»: на практике это администратор компании (или администратор платформы).
Дизайнер процессов автоматически этого права не получает. Список находится на странице настроек, а не в редакторе;
попросите администратора добавить домен до активации процесса.

<a id="sec-start-and-end"></a>
## 6. Начало и конец процесса
<!-- labels: pd.type.START, pd.type.END, pd.edit.refusal.second_start, pd.edit.refusal.delete_start -->

В каждом процессе ровно одно **Начало** и хотя бы один **Конец**.

* В начало ничего не входит, из конца ничего не выходит.
* Начало нельзя удалить («Начало удалить нельзя.») и нельзя добавить второе («Начало может быть только одно.»).
* Каждый шаг должен быть достижим от начала, а от каждого шага должен быть путь к концу.
* Кто может запустить процесс, решает право запуска определения, а не рисунок.

<a id="sec-validation-messages"></a>
## 7. Сообщения проверки
<!-- labels: pd.edit.violations, pd.edit.valid, pd.edit.checking, pd.edit.checkFailed -->

Редактор проверяет процесс по ходу работы: **Проверка…**, затем **Без ошибок** или число проблем и список
**Проблемы, найденные проверкой**. Если проверка не запустилась, вы увидите
«Проверить не удалось; сохранить всё равно можно.», а сервер проверит ещё раз при сохранении и активации. Сообщения приходят с сервера на английском
языке на любом языке интерфейса. `<step>`, `<arrow>` и `<other>` ниже означают идентификатор шага или стрелки.

| Сообщение | Что делать |
|---|---|
| No START node found in the definition graph | Добавьте шаг **Начало**. |
| Found N START nodes; exactly one is required | Удалите лишние начала. |
| No END node found in the definition graph | Добавьте шаг **Конец**. |
| Duplicate node ID '`<step>`' | У двух шагов один идентификатор; удалите один и добавьте заново. |
| Node count N exceeds the maximum of M / Edge count N exceeds the maximum of M | Процесс слишком большой; разделите его подпроцессом. |
| Edge '`<arrow>`' has dangling source reference: node '`<step>`' does not exist (также: dangling target) | Стрелка ведёт к удалённому шагу; удалите стрелку или соедините заново. |
| Node '`<step>`' is isolated (insufficient incoming or outgoing edges for its type) | Соедините шаг со входом и выходом. |
| Node '`<step>`' (TYPE) is not reachable from any START node | Проведите к шагу стрелку от начала. |
| Node '`<step>`' (TYPE) has no path to any END node | Проведите от шага стрелку к концу. |
| Cycle detected: edge from node 'A' to node 'B' creates a cycle not passing through a gateway node | Цикл должен проходить через **Решение**; добавьте его. |
| Node '`<step>`' (TYPE) has no default outgoing edge (is_default: true); an instance whose conditions all evaluate false would stop with no matching route | Отметьте одну стрелку как «Маршрут по умолчанию». |
| Edge '`<arrow>`' is a non-default outgoing edge from an EXCLUSIVE_GATEWAY and requires a non-empty condition | Заполните **Условие** или сделайте стрелку маршрутом по умолчанию. |
| Edge '`<arrow>`' is not a non-default EXCLUSIVE_GATEWAY outgoing edge or a HUMAN_TASK outgoing edge and must not have a condition | Очистите условие. |
| Edge '`<arrow>`' is marked is_default but also has a non-null condition | У стрелки по умолчанию условия нет; очистите его. |
| Edge '`<arrow>`' is an additional default edge from EXCLUSIVE_GATEWAY node '`<step>`'; only one default edge is permitted per gateway | Оставьте одну стрелку по умолчанию. |
| HUMAN_TASK node '`<step>`' has at least one really-conditioned outgoing edge but no fallback edge | Добавьте стрелку по умолчанию после задачи пользователя. |
| Node '`<step>`' (HUMAN_TASK) is missing a non-empty 'role' attribute | Заполните **Роль**. |
| Node '`<step>`' (SERVICE_TASK) is missing a non-empty 'endpoint' attribute (and no non-empty 'service_id' attribute is present as an alternative) | Выберите для сервисной задачи функцию, уведомление или скрипт. |
| Node '`<step>`' (SERVICE_TASK) has an invalid 'script_key'/'script_version' pair | Ключ скрипта: строчные буквы, цифры и `_`, начинается с буквы; версия — целое число от 1. |
| Node '`<step>`' (SERVICE_TASK) binds a script and also carries an 'endpoint' or 'service_id' | Оставьте один способ: скрипт или сервис. |
| Node '`<step>`' (SERVICE_TASK) binds a platform call and also carries an 'endpoint', 'service_id' or 'script_key' | Оставьте функцию или другое, но не оба. |
| Node '`<step>`' carries an invalid 'notify' attribute (code) | Уведомление заполнено не полностью; см. раздел 5, код называет поле (например `template_missing`, `recipient_missing`). |
| Node '`<step>`' (SERVICE_TASK) has an invalid 'timeout_ms' attribute; must be an integer in 1..300000 | Укажите целое число миллисекунд, не больше 300000. |
| Node '`<step>`' (TIMER) has an invalid 'duration_iso8601' attribute | Запишите длительность в формате ISO 8601, например `PT30M`. |
| ... 'escalation_timer_duration' / 'reminder_timer_duration' invalid, or its role missing, or a role without a duration | Для эскалации и напоминания нужны и корректная длительность, и роль. |
| ... 'required_outputs' / 'required_permission' / 'distinct_from' invalid, or used on a step that is not a HUMAN_TASK | Эти настройки есть только у задач пользователя и только с корректными значениями. |
| Node '`<step>`' (HUMAN_TASK) lists '`<other>`' in distinct_from, but no node '`<other>`' exists in this definition / is not a HUMAN_TASK / is reachable only after '`<step>`' | Правило «должен выполнить другой человек» должно называть существующую задачу пользователя, стоящую раньше. |
| Node '`<step>`' (HUMAN_TASK) lists itself in distinct_from | Уберите шаг из его собственного списка. |
| Edge '`<arrow>`' (текст ошибки условия) | В условии синтаксическая ошибка; сообщение указывает место. |
| Extension point '...' names node '`<step>`' which is not in the definition graph | Точка расширения указывает на несуществующий шаг. |

Сообщения о платформенных шагах, шаблонах уведомлений и интерфейсах подпроцессов приходят в том же списке.
Платформенный шаг в определении обычной компании отклоняется; см. раздел 11.

<a id="sec-save-version-activate"></a>
## 8. Сохранить, версия, активировать, откатить одним действием
<!-- labels: pd.edit.saveDraft, defs.publish, defs.activate, defs.rollback, defs.copyAsDraft, pd.edit.discard -->

* **Сохранить черновик** сохраняет изменения как версию «Черновик». Если определение уже было активным, сохранение
  создаёт новый черновик со следующим номером версии; активная версия не затрагивается. Если кто-то изменил
  определение, пока вы правили, вас спросят: «Всё равно сохранить» или «Перезагрузить». **Отменить изменения**
  отбрасывает несохранённое.
* **Опубликовать сохранённую версию** (в редакторе) или **Активировать** (в списке) включает черновик. Прежняя
  активная версия становится «Устарело»; новые запуски идут по новой версии, идущие запуски остаются на своей.
  Активация заново выполняет полную проверку и прогоняет тестовые случаи (раздел 9). Если она отказала,
  проблемы показаны под кнопкой.
* **Копировать как черновик** делает редактируемую копию любой версии.
* **Откатить…** (в списке) возвращает предыдущую версию в активные одним действием. Выберите версию и подтвердите.
  Откат отклоняется, если эта версия никогда не была активной или уже активна.
* **Архивировать** убирает версию, которая больше не нужна.

<a id="sec-test-cases"></a>
## 9. Тестовые случаи перед активацией (G16)
<!-- labels: -->

Определение может объявить **тестовые случаи**: исходный набор значений, задачи людей, которые нужно выполнить
автоматически, и чем должен закончиться запуск. Перед включением версии каждый объявленный случай проходится
в памяти (запуск не создаётся, почта не отправляется). Если один случай не прошёл, активация отклоняется и ничего
не меняется. Отказ называет случай и короткую причину, например `status_mismatch` (запуск закончился иначе),
`variable_mismatch` (значение не то, что ожидалось) или `node_not_visited` (запуск не дошёл до названного шага).
Сами значения он не показывает.

Версия без тестовых случаев активируется как раньше. Писать тестовые случаи на экране **пока недоступно**;
сейчас они часть данных определения и описаны в `docs/definition-test-cases.md`.

<a id="sec-runs-and-retry"></a>
## 10. Где смотреть запуск: экземпляры, журнал шагов, повтор
<!-- labels: pd.replay.modeReplay, pd.replay.listLabel, pd.state.error -->

* Раздел **Экземпляры** в боковом меню показывает запуски. Откройте один: шаги на схеме окрашены по состоянию
  («Выполнено», «Активно», **Ошибка**, «Пропущено», «Не достигнуто»).
* Режим **Повтор** проходит по записанным шагам по одному. Список **Записанные шаги** показывает, кто, когда и с каким
  результатом выполнил каждый шаг.
* Платформенный шаг или уведомление, которые не удались слишком много раз, попадают в **DLQ** (очередь
  необработанных, в боковом меню). Откройте запись и нажмите «повторить»: шаг выполнится ещё раз. Если получилось,
  запуск продолжится. Повтор не даёт лишних прав; нужно право на работу с очередью и, для платформенного шага,
  полномочия платформы.

<a id="sec-platform-only"></a>
## 11. Что может только оператор платформы
<!-- labels: -->

* **Платформенные шаги** (функции, которые создают или меняют арендатора, например регистрация компании) существуют
  только в арендаторе платформы. Определение обычной компании не может их содержать; редактор отклонит такой шаг.
* Каталог функций задаёт платформа: новые функции добавляются изменением кода, а не в редакторе. В арендаторе
  компании выбор функции может показать «Каталог платформенных функций недоступен в этом арендаторе.»
* Добавление исходящего адресата — не право дизайнера (раздел 5).
