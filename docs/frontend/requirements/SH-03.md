# SH-03 — Role-aware navigation `[MUST]`

> The global sidebar/navbar SHALL display only the navigation items the current user's role set permits. Items for areas outside the user's permissions SHALL be hidden entirely, not greyed out.

**See:** IDN-03 (role permission matrix), SH-01 (role set decoded after login), Appendix A (navigation structure and per-role gating)

## Implementation note (T-1522, D-114 item 1)

Every sidebar entry declares the permission its page needs next to its route: `NAV_ITEMS` in `AppShell.tsx` for core pages, `navItems` in each module's `index.ts`. The visible set is computed by `visibleNavGroups` (`web/src/components/layout/navVisibility.ts`) from `GET /me/access`; a group with no visible entry is hidden, and while access is loading or failed nothing gated shows. Import data also needs at least one importable type: each `ModuleImportType.permission` is the module write permission the server needs for that type, and `getImportTypesFor` lists only the types the user holds (a storekeeper sees only `stock_opening_line`). The menu is presentation only; direct URLs stay refused by the server and by `RequirePermission`. Tests: `navVisibility.test.ts` (role sets read from `priv/permission_matrix/effective.golden`), `navGuardParity.test.tsx` (an entry's permission equals its route guard), `navRoleWalk.test.tsx` (every visible entry opens, per role), and the live-backend `nav-role-walk.e2e.spec.ts` (accounts in `E2E_STOREKEEPER_USER/PASSWORD`, `E2E_WORKER_*`, `E2E_SCOPED_*`; skipped when unset).
