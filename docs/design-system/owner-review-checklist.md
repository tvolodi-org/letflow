# Owner review checklist: every finding with the lesson added

Task T-1956, owner decision D-145 (relayed by the PM on 2026-11-14). Docs only.

The owner's reviews are there to teach the team, not to find its errors. So every finding he made is listed here
with the **lesson added**: a rule in a design-system doc, a line of this checklist, or a guard test. That way the
same finding should not come back. Every design gate and every GUI review checks the whole list on every UI task,
with screenshots at 1440 and 390 px. The verdict carries one line: "owner checklist: all items checked", or the
numbers of the items that fail. Any failing item that applies to the task is a FAIL.

This file is now the source of the list. The first version was the 16 items in the team's design-system skill (the
lab file `project/skills/letflow-design-system.md`, section "Owner review checklist (D-145, 2026-11-14)").
Items 1 to 16 keep that text and its numbers. Items 17 to 21 come from the gate walks.

## How to read the columns

- **Finding**: what the owner saw, on which screen, and which task fixed it. "Open" means the fixing task is not
  merged yet.
- **Rule**: the design-system doc section that states the rule. "This line" means there is no doc section yet, so
  the checklist line itself is the rule.
- **Guard**: a test or lint that fails when the rule is broken, and where it runs:
  - *Frontend gate*: `npm run check` in CI, which runs `web/src/**/__tests__`, `web/tests/unit` and `web/tests/guards`.
  - *Stock e2e*: `.github/workflows/stock-e2e.yml`. It runs only the `gate-b-*` specs it names, on a matching path
    change and every night.
  - *Mobile gate*: the Mobile gate job in `.github/workflows/ci.yml`.
  - *Local e2e only*: a Playwright spec under `web/tests/e2e/` that no CI job runs (`npm run check` leaves out
    `tests/e2e/**`).
  - **MISSING**: no guard exists. The table at the end lists what a guard would check.
- **Check at 1440 / 390**: what the reviewer does on the screenshots or in the harness at each width.
