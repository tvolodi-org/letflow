# G-01 — generated real-HTTP route × role × tenant × request-shape matrix

Gap **G-01** of the security coverage map (`docs/security-coverage.md` §4,
lab repository): *"Generated real-HTTP route × role × tenant × request-shape
matrix (from the route inventory + permission golden), with foreign/missing
byte identity and no-write assertions."*

The defect classes it names:

* **T-2588** — a company `TENANT_ADMIN` storing a `platform_call` graph
  through PUT/PATCH (a write path the create-path test did not cover).
  **Covered**, and proven by mutation: removing `check_platform_call_tenant`
  from the update path or from the create path makes the probe fail (rule M8
  and test G-01-C8; see "Mutation checks").
* **T-2444** — MS-S4 sent foreign variables but not tenant B's
  `definition_id`. **Partly covered**: every mutating route receives B's
  `definition_id` both at the top level and inside `initial_variables`
  (`POST /instances`' required start shape), and M5/M6 check that A neither
  writes B nor learns B's ids. The module start routes' own body shapes are
  not generated (see "Scope boundary").

## What the probe is

A mechanical, deterministic, model-free ExUnit probe. The matrix itself (routes,
roles, oracle, id pools) is generated; the parts fixed by hand are the T-2588
anchor test's three policy keys (G-01-C8), the one privileged request body
(`G01.privileged_body/1`), the M8 exclusion list (`api_tokens`,
`audit_entries`), the marker and the missing id:

| input | source |
|---|---|
| routes | `Letflow.Support.RouteInventory.routes/0`: every `{method, path, policy key}` of every router mounted by `Letflow.Plugs.ApiPipeline` and of every catalogue module router (451 routes in the matrix today) |
| roles | `Letflow.Api.Authorization.roles/0` (nine) |
| oracle | the committed golden `priv/permission_matrix/effective.golden` (role × permission), through `Authorization.required_permission/1` (key → permission), the platform rule (a platform-scope permission, and every grant of `PLATFORM_ADMIN`, needs the configured platform tenant), the tenant's stored grant overlay (`Letflow.Api.TenantGrants.load/1`) and the concealed keys of `Letflow.Plugs.Authorize` (`@concealed_keys`, read from its source: their denial is the plain 404) |
| callers | a real API token per role in an ordinary (company) tenant A (A's `PLATFORM_ADMIN` is the stored legacy token shape), and the platform tenant P's `PLATFORM_ADMIN`; every request goes through the FULL `Letflow.Router` pipeline (bearer token, `x-tenant-slug`) |
| foreign tenant | tenant B with every golden module installed; its id pool is the smallest `id` of every B table with a uuid `id` and a row (`G01.foreign_pool/1`, derived from the database) |
| own pool | the same rule over A's tables, with `process_definitions` pointing at a DRAFT of A (the definition PUT/PATCH write path works on drafts only) |
| request shapes | `missing`: a nonexistent uuid in every path parameter, for every caller × route; `foreign`: the same request with each id of B's pool, for the first A caller the oracle allows, on every route with a parameter; `own`: every MUTATING route with a parameter again with each id of A's own pool, for the first A caller the oracle allows (the write path on real records) |
| body | every mutating verb carries one privileged body (`G01.privileged_body/1`), the union of the route families' write shapes: the definition shape (`name`, `version`, `description`, and a `graph` whose SERVICE_TASK carries a `platform_call` attribute with a unique marker, `G01.privileged_graph/0`), the instance start shape (`initial_variables` with B's tenant id and `definition_id`), and top-level attributes naming B (`tenant_id`, `tenant_slug`, `definition_id`, `instance_id`, `record_id`, `roles: [PLATFORM_ADMIN]`, `platform_call`) |

Every golden module is installed in A and B, so a module route reaches its
permission check instead of the not-installed 404; the two feature flags that
close routes to every caller (`:record_triggers_enabled`, `:scheduled_jobs`)
are switched on for the test (restored on exit).

Every request runs in a transaction that is always rolled back, so each one
sees the same starting state (no order dependence). The written tables come
from PostgreSQL's own per-transaction counters
(`pg_stat_get_xact_tuples_inserted/updated/deleted`, the functions behind
`pg_stat_xact_user_tables`, read for the oids of A's, B's, P's and `public`'s
tables), which count attempted inserts, updates and deletes, also rolled-back
ones. For a request with a body, the tables of A it wrote are searched for the
marker before the rollback (rule M8). A request whose transaction a handler
left aborted (a failed nested transaction, or a rescued database error) can
commit nothing and is not searched: a query on an aborted transaction would
disconnect the sandbox connection, so the probe asks DBConnection with an
empty nested transaction first.

The probe has an OBSERVE half (`G01.observe/1`) and a CHECK half
(`G01.violations/2`, pure functions over the observations). The real tree,
the seeded rogue router and the T-2588 anchor go through the same two
functions.

### Files, tags and cost

The real-tree matrix is cut into `G01.shard_count/0` = 4 shard files, so that
each tagged file stays within its share of the checks step's probe budget
(`project/scripts/lf.sh` in the team repository: 300 s divided by the number
of tagged probe files; 12 files today, share 25 s). Shard `i` holds the matrix
routes whose index in the sorted route list is `i` modulo 4; each shard
compares its violations with the ratchet lines of its own routes.

| file | what it holds | tag | declared cost |
|---|---|---|---|
| `test/support/security_probe/g01.ex` | generator, oracle, observe and check halves, shards, ratchet reader | — | — |
| `test/support/security_probe/g01_case.ex` | fixture world (tenants, tokens, installs, A's draft), check context, `run_shard!/1` | — | — |
| `test/support/security_probe/g01_rogue_router.ex` | the seeded broken router (one defect per rule), mounted nowhere | — | — |
| `test/fixtures/security_probes/g01/ratchet.txt` | the pinned violations (reviewed narrowings and open findings) | — | — |
| `test/letflow/security_probe/g01_route_role_matrix_test.exs` | completeness, non-vacuity, shard coverage, T-2588 anchor | `:security_probe` | `probe_cost_s: 8` |
| `test/letflow/security_probe/g01_matrix_shard_0_test.exs` … `_3_test.exs` | the real-tree matrix, one quarter each | `:security_probe` | `probe_cost_s: 22` each |

lf.sh's own planner on this tree (`plan_probe_chunk`, 2026-11-23): "security
probes: 12 probe(s) in the checks set, declared cost 179s of the 300s budget",
all five G-01 files in the chunk. The files are also in the product's
bounded-CI safety set (`scripts/ci_select_tests.py`,
`STANDARD_SECURITY_PROBE_TESTS`), so CI runs them on every bounded run.

Measured on this host (2026-11-23, one file per `mix test`): main file 7.4 s;
shards 17.6 s (load 5.2), 20.4 s (load 9.4), 22.6 s (load 9.1) and 32.7 s
(load 13.7). Each shard sends about 2 150 requests (1 130 matrix, about 580
foreign, about 430 own) in 9–12 s on a normally loaded host; the rest is the
fixture world (three committed tenants and two full module installs, about
8 s). On a host above load 12 a shard exceeds its declared 22 s.

## The rules

| rule | assertion |
|---|---|
| M1 | a caller the oracle denies gets the canonical denial: status, content type and body bytes (`trace_id` removed) equal to `Response.forbidden(conn, "insufficient permissions")`, or to `Response.not_found/1` for a concealed key |
| M2 | a denied request writes nothing in A, B, P or `public`, except the caller's own `api_tokens` row (`last_used_at`) |
| M3 | a caller the oracle allows is not given the canonical 403 (an over-denial: a second gate narrows the golden) |
| M4 | for an allowed A caller, the answer for each of B's ids equals the answer for a nonexistent id (status, content type, body with the id replaced by a placeholder) |
| M5 | no request of an A caller writes a row of B |
| M6 | no answer to an A caller contains B's schema name, slug, tenant id or any id of B's pool |
| M7 | no generated request crashes the pipeline or answers 5xx |
| M8 | no request of a company-tenant (A) caller leaves a row of A, other than `api_tokens` and `audit_entries`, holding the privileged body's `platform_call` marker: a company tenant never stores a platform call (T-2588, decision record 0094). `audit_entries` is not searched because the audit trail records refused input by design (`tenant_settings.reject_unrecognized_keys` keeps the values of the rejected keys) |

Each shard's real-tree violations must equal the ratchet lines of its routes
in `test/fixtures/security_probes/g01/ratchet.txt` exactly: a new violation
fails, and so does a pinned line that no longer occurs (a fixed finding leaves
the file; the ratchet only tightens).

  `G01.violations/2` (its condition replaced by `false`) makes the rogue test
  fail on that rule's own assertion; restored, it passes. M8 is asserted the
  same way (G-01-N8).
* Product, T-2588 (attempt 2): `:ok <- check_platform_call_tenant(graph, prefix)`
  replaced by `:ok` in `Letflow.Definitions`' update path → the anchor test
  fails ("PATCH /definitions/:id answered 200") and shard 2 reports
  `M8 A_PROCESS_DESIGNER PUT /definitions/:id`; the same in the create path →
  shard 2 of the current 4-shard cut (`POST /definitions`) reports `M8
  A_PROCESS_DESIGNER POST /definitions` and `M8 A_TENANT_ADMIN POST

  500 (`:entity_type_not_found`, logged by the exam router) for CANDIDATE and

## Scope boundary (what this probe does NOT cover)

* **Interactive (OIDC) callers and scoped grants.** The callers are API
  tokens with tenant-wide roles. The allowed path of the routes pinned under
  M3, and node-scoped callers (SF-05), are outside this probe.
* **Route-specific valid bodies.** One body is sent to every mutating route.
  It is valid for the definition write routes (G-01-C8 proves they reach the
  tenant check) and carries `POST /instances`' required `initial_variables`;
  most other routes refuse it at their own validation (missing required
  fields, wrong types), so their write paths are reached only as far as that
  validation. Each route family's own valid body (module documents, module
  start routes with B's `definition_id`, solution packs) is not generated.
  Malformed bodies, wrong content types and oversize inputs are G-13's
  matrix.
* **Activation, import, promotion and rollback of a definition.** M8 sees a
  platform call stored by any route the body reaches; the activation and
  import paths take other inputs (a stored draft, an archive) and are G-02's
  write/activation path inventory.
* **Response fields by role** (INV-2): the probe compares whole answers for
  identity and looks for B's identifiers; it does not check a per-route field
  allowlist.
* **Foreign and own ids of tables that are empty.** The pools hold a real id
  for every table with a row after the module installs (nine tables in B
  today: `api_tokens`, `audit_entries`, `entity_definitions`,
  `entity_field_restrictions`, `entity_views`, `event_type_registry`,
  `process_definitions`, `tenant_modules`, `users`). Instances, tasks and
  records are not seeded yet; a richer world widens M4/M8 without a code
  change.
* **Path parameters that are keys, not ids** (`:entity_type`, `:process_key`,
  `:slug`): they receive the same uuid as every other parameter.
* **Test-only and QA-only modules** (`fixture`, `runtime_demo`): not in the
  golden; G-01-C3 proves none of them is shipped.
* **Wall-clock timing** between foreign and missing ids is not compared.
