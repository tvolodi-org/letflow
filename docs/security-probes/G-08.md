# G-08 — normal-run / cleanup-replay equivalence of the UAT safety checks

Class: TOOL (D-184/D-186). The probe is a mechanical test (no model): it runs the two paths of the UAT
runner against fake servers and compares the safety checks each of them made. It runs under the
`:security_probe` tag and is a mandatory test in the bounded standard backend selection. Declared cost:
**15 seconds** (`probe_cost_s: 15`).

The gap it closes (team repository, `docs/security-coverage.md`, G-08): the T-2606 cleanup replay omitted
the platform residue check and reported PASS with an instance still ACTIVE. A safety check that one path
makes and the other does not is a hole of that class.

## What is derived

- The runner (`scripts/uat/runner.py`) has two paths: `run` (a process or a chain) and `replay_cleanup`
  (the cleanup list of an aborted run). Every safety check of a path leaves a row in the run log, so the
  probe reads the checks each path **actually made** from `run.jsonl` — it does not trust a declaration.
- `test/fixtures/security_probes/g08_uat_safety_checks.txt` is the reviewed expectation: one line per
  check kind (`kind | run | replay | note`). `yes` = the path makes the check, `no` = it does not,
  `except` = a reviewed divergence (the run makes the check, the replay does not, the note says why).
  A new check of the runner needs a line here: the probe fails until the line is reviewed.
- The two reviewed divergences are the **stable-build wait** (a run waits for a stable build before its
  first step; a replay judges the deployment that is already there and must clean up even when it is
  broken) and the **expected build** (`--build-sha` is an option of the run command; the cleanup command
  has none, so the replay judges the build that is deployed).
- A run **persists what it promises its cleanup replay** (`safety.json` in the run dir): the baselines the
  replay must find and the platform watch it must keep. A replay that cannot find one of them **fails
  closed**: the residue row says the replay cannot judge the run, and the replay exits 1. It never passes
  a run it cannot judge (the T-2606 defect).
- The probe is pure: fake servers on 127.0.0.1, a fake token command, a fake stable-build script, no
  database, no network, no clock, no model. Its scenario is one company tenant and one platform tenant,
  with a definition that is changed and rolled back, an instance that is started and cancelled, and a
  cleanup step the replay has to run.

## What the probe does not cover

- The retired-tenant guard and the `--allow-create` switch live in the command line, not in the runner:
  they are the same for both paths and are covered by the command-line tests of the suite.
- The scenario has no chain with per-tenant overrides; a chain entry runs in its own tenant, and the
  residue baseline of that tenant is part of the same expectations file.
- The stable-build wait and the expected build cannot be *forced* in the scenario beyond what the fake
  host offers; they are the two reviewed divergences above and their rows are read from the log.

## Running and refreshing

```sh
mix test test/letflow/security_probe/g08_uat_safety_equivalence_test.exs
```

The probe alone (from the repository root):

```sh
python3 -I -B -m unittest discover -v -s scripts/uat/tests -p "test_safety_equivalence.py"
```

After a reviewed change of the runner's safety checks, regenerate the expectation file from the final
tree, inspect its diff and rerun the probe. A refresh is not a way to bypass a finding: the reviewer must
account for every added, removed or changed line.
