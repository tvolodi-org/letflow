# G-06 — Outbound HTTP-client / call-site inventory and dispatch-time probes

Gap **G-06** of the team repository's `docs/security-coverage.md` §4:

> Outbound HTTP-client/call-site AST inventory plus common dispatch-time
> SSRF/redirect/error-sanitisation probes.

Class: **TOOL** (D-184/D-186 ratchet: mechanise the security gates). The probe
is mechanical — no model, no network, no clock — and it runs in the `checks`
step for every backend change. The enforcement is NOT "the probe files are
ordinary test files" (that only runs them when they change): it is the
`@moduletag :unit` in both files, which puts them in the team runner's unit
tier (`mix test --only unit`, run on every non-rework backend change), plus
the product's own bounded-CI safety set (`scripts/ci_select_tests.py`,
`STANDARD_SECURITY_PROBE_TESTS`), which makes them mandatory on every bounded
run. The tag `:security_probe` and the per-file cost `@moduletag
probe_cost_s: N` say so; the operator's `lf.sh` hook can select the tagged set
once it exists.

## What is delivered

- `test/letflow/security_probe/g06_outbound_http_inventory_test.exs` — the AST
  inventory of every outbound call site in `lib/` and the seven rules I1–I7.
- `test/letflow/security_probe/g06_outbound_dispatch_probes_test.exs` — the
  common dispatch-time probes P1–P3, run through every channel.
- `test/fixtures/security_probes/rogue_outbound_client.ex` — the seeded
  failing case (a deliberately broken outbound channel; text, never compiled).
- `docs/security-probes/G-06.md` — this class table.

## The inventory

Seven outbound call sites exist in `lib/`, all of them `:httpc.request/4`:

1. `lib/letflow/webhooks.ex`, function `do_dispatch_http/3` — `:tenant_input`
   (the subscription's tenant-set `target_url`).
2. `lib/letflow/engine/service_task_dispatcher.ex`, function
   `do_http_transport/3` — `:tenant_input` (the service task's rendered
   endpoint URL).
3. `lib/letflow/voice/http.ex`, function `request/5` — `:platform_config`
   (the operator's voice provider base URL).
4. `lib/letflow/oidc/realm_probe.ex`, function `exchange/2` —
   `:platform_config` (the operator's Keycloak base URL).
5. `lib/letflow/signup/realm_users.ex`, function `http/3` —
   `:platform_config` (the operator's realm provisioner base URL).
6. `lib/letflow/signup/realm_provisioner.ex`, function `http/5` —
   `:platform_config` (the operator's realm provisioner base URL).
7. `lib/letflow/obs/alerts.ex`, function `deliver_with_retry/4` —
   `:platform_config` (the operator's alert hook destination URL).

`:tenant_input` and `:tenant_config` call sites must be reached through
`Letflow.Webhooks.UrlValidator.validate/1,2`; `:response_derived` is refused
outright; `:platform_config` URLs are the operator's own network and are not
tenant-controlled, so INV-9 does not require the shared validator for them.

## Class table

Every case of the probe, the behaviour it demands, the authority it rests on
and the test that proves it. `case` is the surface the rule is about,
`expected` is what the probe demands, `authority` quotes the invariant or
decision the rule comes from, `test` names the test that fails when the rule
is broken.

Every rule that `violations/2` computes (I2 to I7) is driven through that
SAME aggregate entry point by a synthetic case, and it is the entry point the
real-tree test uses: a rule that is dropped from the accumulator fails the
synthetic cases instead of passing quietly. I1 is the completeness check of
the scan itself (the scan must find exactly the seven real call sites), and
it is proven by the inventory test. The "Non-vacuity" section below lists the
mutation run that proves this for I5 and I7.

## Non-vacuity

The probe ships its own failing case:
`test/fixtures/security_probes/rogue_outbound_client.ex` is a deliberately
broken outbound channel (a `Req.get/1` call, an `autoredirect: true` option,
a tenant URL that reaches `:httpc.request/4` with no validator on its path,
and a second unchecked entry point). It is TEXT under `test/fixtures/` —
never compiled, never run — and the probe's own test drives it through the
aggregate entry point and proves that every one of those defects is flagged.
The inventory itself is checked for completeness: the scan must find exactly
the seven real call sites, so a scan that silently finds nothing cannot pass.

The rules are also checked against MUTANTS of the probe (the mutation script
is kept with the task notes; each mutant is a one-line copy of the probe and
each was run against the probe's own suite):

- the I7 message neutered → three tests fail, among them "I7: a request that
  does not disable redirect following is flagged through the aggregate entry
  point";
- `dispatch_violations` dropped from the accumulator → "I5: a tenant-influenced
  call site without the validator is flagged through the aggregate entry
  point" fails;
- `redirect_violations` dropped from the accumulator → the same I7 test fails;
- the redirect option looked for in the whole enclosing function instead of
  in the request call's own options (the earlier false negative) → "I7: the
  check is on the request call itself, not on the enclosing function" fails.

## Cost

- `test/letflow/security_probe/g06_outbound_http_inventory_test.exs` declares
  `probe_cost_s: 7`; measured 6.6 s (one AST pass over `lib/`, no database).
- `test/letflow/security_probe/g06_outbound_dispatch_probes_test.exs` declares
  `probe_cost_s: 1`; measured ~0.1 s (eight tests, every peer a local
  listener on 127.0.0.1).

Both files are tagged `:security_probe` and `:unit`; the whole tagged set of
this probe measures 11.7 s (31 tests), well inside the five-minute budget of
the `checks` step.

## Residual limits

- The AST rules see literal module names and literal option lists. A client
  reached through a variable receiver, a validator reached through `import`,
  or an option built by a macro is not seen.
- The redirect rule resolves a request's options only when they are a literal
  list, a literal list concatenated with something, or a local variable bound
  to one. An option list built at runtime is treated as NOT disabling
  redirects (the probe fails closed) and needs a human to classify it.
- The dispatch-time probes P1–P3 run against the channels whose transport is
  reachable without a database (`service_task_dispatcher`, `voice`). The other
  five channels are covered by the AST rules I1–I7; `webhooks.ex` is covered
  by the AST rules plus the product's own `test/letflow/webhooks_test.exs`.
- The general canary-secret harness (every input encoding to every log,
  audit row, DLQ entry and artifact) is gap **G-04**, not G-06.
