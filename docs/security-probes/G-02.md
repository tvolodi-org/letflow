# G-02 — writer and start-path AST inventory

Class: TOOL (D-184/D-186). The probe is pure Elixir AST analysis: no model, database, clock, network,
process ordering or random input. It runs under the `:security_probe` tag and is a mandatory test in
the bounded standard backend selection. Declared cost: **15 seconds** (`probe_cost_s: 15`).

## What is derived

- `test/support/security_probe/g02.ex` parses every `.ex`/`.exs` below `lib/` and `priv/`. It
  normalises pipes; resolves full, grouped and renamed aliases; sees calls, captures and literal/dynamic
  `apply/3`; and includes the repository variables used by transaction and Multi callbacks, plus any
  other receiver whose method name is a Repo mutation verb (`insert`, `insert!`, `insert_all`, `update`,
  `update!`, `update_all`, `delete`, `delete!`, `delete_all`). Documentation and type attributes are
  excluded, so prose and `Repo.t()` do not become inventory entries.
- `test/fixtures/security_probes/g02_repo_inventory.txt` is the reviewed, line-independent inventory
  of **every** Repo call (reads, writes, transactions, query and control verbs), every `Ecto.Multi`
  call and every repository-variable call (a `$name` target). A new, removed or re-argumented call
  makes W1 fail. Moving a line alone does not.
- A local transitive call graph derives every public function in the `Letflow.Definitions` namespace
  whose closure reaches a repository write: direct Repo writes, Multi writes, callback-repo writes and
  dynamic applies. The module set comes from the namespace, not from a hand-written list, so a
  definition writer outside the first three reviewed modules is still classified. D1's classes are
  `graph_write`, `switch_on`, `status_only`, `supporting_write`, `activation_write`, `review_write`,
  `reactivation`, `snapshot_write`, `pack_write` and `override_write`; an unclassified new path fails.
- S1 is the closed start inventory: HTTP `Engine.create/2`, the three module starts, the scheduled-job
  `Engine.create/2` capture (repeated for the three arities generated by `run/3`'s two defaults), both
  `SubProcess.append_start_multi/7` call sites (initial start and continuation) and both
  `SubProcess.prepare_child_activation/4` call sites (the child activation that creates the child
  instance snapshot). S2 separately inventories every syntactic write of `:module_start`: the
  `Keyword` verbs (`put`, `put_new`, `replace`, `replace!`, `delete`), the `Map` verbs (`put`,
  `put_new`, `replace`, `replace!`, `delete`), `List.keystore/4` and a literal keyword pair, through a
  renamed module (`alias Keyword, as: KW`) as well. Only stock, assets and maintenance module code may
  supply it, and only as literal `true`. Dynamic `apply/3` to Repo, Multi or a start target is retained
  as `:dynamic`, never treated as a harmless unknown call.
- S3 states where the two module-start gates live and proves that every Engine start entry reaches one
  of them: `Letflow.Engine.gate_module_only_start/2` for a root instance and
  `Letflow.Engine.SubProcess.refuse_module_only_child/4` for a SUB_PROCESS child. An Engine entry that
  can start an instance without one of them is reported.

This is an inventory/ratchet, not a claim that every listed writer is tenant-safe. Existing semantic
and route probes retain their own verdicts.

### Limits, stated rather than hidden

- Non-literal dynamic modules/functions and macros defined elsewhere cannot be resolved without
  executing code. A computed `module_start` value fails closed (`:computed`) rather than being guessed.
- A `module_start` merged from a **computed** keyword list (`Keyword.merge(opts, other)`) cannot be
  resolved without executing code; a merge of a literal list that carries `:module_start` is seen.
- A receiver whose method name is a Repo mutation verb is retained conservatively as a possible
  repository write, so the inventory can contain a row that is not a database write. The reviewer
  confirms every added row.
- The call graph is a fixpoint over local and remote calls. A call through a variable (an
  indirection) and a call into a module outside the scanned tree are not resolved.
- The inventory is a static inventory: it says which writers and starts exist, not that each of them
  carries the right tenant scope or authorisation.

## Running and refreshing

```sh
mix test --only security_probe test/letflow/security_probe/g02_writer_start_inventory_test.exs
```

After a reviewed source change, regenerate the inventory from the final tree, inspect its diff, and
rerun the probe:

```sh
MIX_ENV=test mix run --no-start -e 'alias Letflow.TestSupport.SecurityProbe.G02; File.write!("test/fixtures/security_probes/g02_repo_inventory.txt", G02.render_repo_inventory(G02.scan()))'
```

A refresh is not a way to bypass a finding: the reviewer must account for every added or removed row.
