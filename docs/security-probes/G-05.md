# G-05 — audit-writer × caller matrix and database-row schema

Class: TOOL (D-184/D-186). This is a deterministic mechanical probe: no model, network, wall-clock
assertion or order dependence. Both modules carry `@moduletag :security_probe`; the matrix declares
`probe_cost_s: 20` and the real-row probe declares `probe_cost_s: 20` (**40 seconds total declared**).
Both are mandatory in `STANDARD_SECURITY_PROBE_TESTS`, so the bounded backend selector includes them
on every standard change, including a web-only change. The matrix half is also tagged `:unit` (it reads
no database), so it already runs in the team's checks step; the row half needs the database and runs
with `mix test` for its own files and in the product's bounded plan.

## What is derived

`test/support/security_probe/g05.ex` parses every production `.ex`/`.exs` below `lib/` without
executing it. It strips documentation/type attributes, normalises pipes, resolves full/grouped/renamed
aliases — the module's own and the ones the file declares above it — and follows literal maps, local
`attrs` assignments and simple local attribute builders. It emits one line-independent row per direct,
`apply/3`, `Kernel.apply/3`, `:erlang.apply/3` or captured (`&Audit.insert_entry/3`) call to
`Audit.insert_entry/3` or `Audit.append_multi/4`, and per call reached through an `import` of
`Letflow.Audit`: an import binds the module's functions, so a bare `insert_entry/3` IS a call to the
central writer and cannot leave the inventory. A dynamic `apply` to Audit is a computed writer row,
not an invisible bypass.

The checked-in matrix contains **154 call sites in 99 files: 123 `insert_entry/3` and 31
`append_multi/4`**. It is stored beside the probe module, at
`test/support/security_probe/g05_audit_writer_matrix.txt`, and not under `test/fixtures/`: the
shipped-definition scans read every file under `test/fixtures/` and refuse the string `reminder_`,
which a real audit-writer call site (`Letflow.Engine.record_reminder_fired/3`) legitimately contains.
Each row records containing module.function/arity and occurrence, writer, actor
class, action, known field set, and before/after payload shape. Added, removed and re-attributed callers
fail M1. Nine remote/computed attribute builders are marked `computed`, never guessed; their call sites
still remain pinned. The required-field and literal-payload rules apply to the other 145 statically
readable call sites. The actor classes of the 154 rows are 119 `caller`, 21 `nobody`, 9 `computed` and
5 `sentinel`; no call site names a person literally, so none states a kind.

Actor classes describe the actor a call site SUPPLIES: `nobody` (no actor), `sentinel` (one of the
platform/system ids — the all-zero UUID family, including `EventStore.platform_actor_id/0`),
`person` (a UUID literal that names a person), `non-person` (any other literal), `caller` (an actor
the call site does not resolve here, so the writer decides), `mixed`, `missing` and `computed` (an
opaque builder). The persisted kind is the writer's business: `audit_entries.actor_kind` landed on
main (T-2588, D-0094 decision (d)) and `Audit.insert_entry/3` DERIVES it — a UUID actor names a
person (`user`), anything else does not (`system`). So a call site that states no kind is not a
violation, and A1 only checks a call site that DOES state one: the kind must be known, and it must
agree with the actor (`user` only where the actor names a person, `system` only where it names one).
The matrix shows a stated kind next to the class (`actor=caller,kind=user`), so a call site that
starts stating one is a matrix drift rather than a silent change.

`W1` separately refuses any write to the tenant's audit chain outside `Letflow.Audit`: an `Audit.Entry`
struct literal, a call on the audit schema, a bulk write that names the audit table (by table name, by
schema alias, through a module attribute or by an interpolated table name — the form this codebase uses
for its other tenant tables), an `Ecto.Multi` operation that carries the audit schema, or a raw SQL
`INSERT` into `audit_entries`. The write is found per function, so a struct literal in another function
of the same module does not launder it. `P1` rejects literal plaintext under the sensitive keys/suffixes
used by `Secrets.Redaction`, recursively through before/after maps. The existing `credential` values are
allowed only when they are the reviewed actor mechanism expression (`Map.get(actor, :credential)` or the
field form), not a credential secret. A literal credential value still fails.

A bypass is refused by `W1`, not recorded in the matrix: the matrix is the inventory of the *central*
writers' callers, so a caller that never reaches `Letflow.Audit` has no matrix row. `W1` is what makes
such a write fail the build.

This is a writer/row ratchet, not a general taint proof: computed payload builders remain visible in the
matrix, and G-04 owns universal canary propagation. No plaintext literal payload violation was found in
the real tree.

## One aggregate entry point

`scan_sources/1` is the aggregate: it turns a list of `{path, source}` pairs into the matrix rows and
the direct writes of those files. The real-tree tests and the synthetic non-vacuity cases go through
the SAME function, so a rule dropped from the accumulator, or neutered inside its own function, fails
the synthetic cases instead of passing quietly (the convention the sibling G-06 probe states).
`violations/1` is that aggregate's anti-bypass half and `sources/1` reads the tree it scans.

Two cases anchor the aggregate, so the anti-bypass rule cannot look nowhere and pass: **W2** pins that
the aggregate reads every production file below `lib/`, and **W3** drives the seeded rogue writer in
`test/fixtures/security_probes/g05/` through the same aggregate the real-tree rule uses.

## Accepted limits

* A macro, a call through a computed module and a value computed at runtime are not evaluated. A
  remote or computed attribute builder stays `computed` in the matrix, and adding or changing one is
  matrix drift. This is an audit-writer ratchet, not the general secret-taint proof owned by G-04.
* The exhaustive inventory of every Ecto write verb and of every `Ecto.Multi` operation belongs to
  gap G-02 of the coverage map. The rule refuses the audit chain through the verbs it reads (`insert`,
  `insert_all`, `update`, `update_all`, `delete`, `delete_all` and their bang forms) and through
  `Multi.insert/3` and `Multi.insert_all/3`; a verb outside that set is G-02's work.
* A raw SQL write that names the audit table in a way no literal segment carries (a table name built at
  runtime) is not seen.
* A bare name that no `alias` binds is resolved against the modules its scope imports, because such a
  name cannot compile otherwise. The rule fires only on code that does not compile, and it names the
  audit schema only when the resulting path ends in the schema's own last two segments (`Audit.Entry`).
* A module reference whose last two segments are `Audit.Entry` is the audit chain's schema: the tree
  holds exactly one such module (`Letflow.Audit.Entry`), which **W4** asserts, so the rule cannot fire
  on an unrelated schema.

## Baseline findings recorded, not silently fixed

**Fixed upstream since the first delivery.** The first version of this probe recorded the attribution
gap the coverage map names: `Definitions.record_definition_audit/5` wrote `actor_id: nil`, so the
person-driven definition import and every activation, reactivation and transition of a definition were
stored as system actions, and `audit_entries` had no `actor_kind` column at all. Main has since landed
the column and the fix (T-2588, D-0094 decision (d)): the lifecycle writers take the caller, and
`Audit.insert_entry/3` derives the kind. The matrix now shows
`Letflow.Definitions.record_definition_audit/6` as `actor=caller`, and D2 checks the persisted
`user`/`system` values. The gap is closed; the probe pins the fixed shape.

**Still open: a system row that the writer stores as a person.** Five call sites write the platform
sentinel `EventStore.platform_actor_id/0` (`00000000-0000-0000-0000-000000000002`) as the actor:
`Letflow.Engine.append_service_entity_write_audits/4`, `record_reminder_fired/3`,
`record_service_entity_write_refusal_audit/7`, `record_stuck_advance_landed_audit/2` and
`Letflow.Engine.ServiceTaskDispatcher.audit_outbound_request/2`. All five are system actions (a
timer fired, a service step ran, an outbound call went out), but `actor_kind_for/1` derives the kind
from the actor id alone, and the sentinel is a well-formed UUID — so every one of those rows is stored
with `actor_kind = "user"`. That is the "nobody against the system" confusion D-0094 decision (d) set
out to remove, in the rows the decision did not reach. The probe pins the five call sites as
`actor=sentinel` in the matrix, so a sixth one is a matrix drift, and the finding is carried forward
for the operator: fixing it means teaching the derivation that a sentinel id names no person. No
production behaviour was changed by G-05 to make the probe green.

## Running and refreshing

```sh
mix test --only security_probe test/letflow/security_probe/g05_audit_writer_matrix_test.exs
mix test --only security_probe test/letflow/security_probe/g05_audit_row_schema_test.exs
```

Measured locally on the merged tree: matrix 3.1 s for 18 tests; database rows 3.0 s for 3 tests
(6.1 s sequential). A second run on a later merged tree measured 6.8 s and 5.3 s. After the
anti-bypass rewrite the matrix half runs 26 tests in 11.2 s and 14.6 s on two runs (it reads the
tree twice now: once for the matrix, once for the anti-bypass rule), so the declared cost of the
matrix half is 20 s and the declared total is 40 s — still inside the team's five-minute budget for
the tagged set. Both halves are in the bounded backend plan of every standard change.

After a reviewed audit-writer change, regenerate from the final tree, inspect every added/removed line,
and rerun both probes:

```sh
MIX_ENV=test mix run --no-start -e 'alias Letflow.TestSupport.SecurityProbe.G05; File.write!("test/support/security_probe/g05_audit_writer_matrix.txt", G05.render_matrix(G05.scan()))'
```

Refreshing is not a way to bypass a finding: actor changes, computed builders and payload shapes are
part of the review, not formatting noise.
