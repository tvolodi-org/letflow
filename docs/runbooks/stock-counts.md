# Stock counts: the count order (REQ-700, GH #3737)

Module `stock` 0.2.0 keeps the **count order** of an inventory taking (decision 0079 sections 1 to 4
and 9). This slice stops at the issued order: the cut-off, the book quantities, the count sheet, the
differences, signing and posting are REQ-701 and later. No ledger call is made here.

Every default below is an **assumption, owner may change at GATE B**.

## What exists

| Part | Where |
|---|---|
| Record types `count_order`, `count_order_scope`, `count_commission_member` (module-managed, scoped by the column `org_unit_id`, decision 0076 R7) | `priv/modules/stock/pack.json`, generated by `priv/modules/stock/generate_pack.exs` from `priv/modules/stock/entity_definitions/` |
| Document types `count.order`, `count.sheet`, `count.differences`, `count.posting` (prefixes CO, CS, CD, CP, numbering restarts each year) | registered by `Letflow.Modules.Stock.on_install/3` |
| Functions | `Letflow.Modules.Stock.Counts`: `create/3`, `update/4`, `issue/3`, `cancel/3`, `get/3`, `list/3`, `document/3` |
| Routes under `/api/v1/modules/stock` | `POST /counts`, `PUT /counts/:id`, `POST /counts/:id/issue`, `POST /counts/:id/cancel` (permission `StockCountOrder`); `GET /counts`, `GET /counts/:id`, `GET /counts/:id/document` (permission `StockRead`) |

`StockCountOrder` is held by TENANT_ADMIN and PLATFORM_ADMIN only (no role grants). The permission for
the count records, `StockCountRecord`, comes with REQ-701, the first route that uses it.

## Rules

1. One org unit per order. A scoped caller sees and writes only orders of the org units of their scope;
   any other order, an unknown id and another tenant's id answer the same 404.
2. The chair needs a linked user (`chair_without_user`). Only the chair may cancel (`not_chair`).
3. Issue checks, in order: draft state, active employees and org unit, every root linked to the org unit
   (`count_scope_not_linked`), no root below another root of the order (`count_scope_overlaps`), a
   `full` count covers every location linked to the unit (`count_scope_incomplete`), the period is
   positive and at most 96 hours (`count_too_long`). A refusal stores nothing and takes no number.
4. Two open orders (ordered, counting, counted, signed) of one org unit may not share a location or
   one lie below the other (`count_scope_overlaps`). Issuing takes an advisory lock per tenant and org
   unit first, so two overlapping issues at once give one winner.
5. Cancel works from draft, ordered, counting and counted. The issued document is not touched.
6. Times are stored in UTC; the default tenant time zone Asia/Almaty matters only for the paperwork of
   later slices. "Signed" means a paper signature on the printout; count paperwork in phase B is xlsx
   with signer lines.
7. The routes take no client idempotency key: a retried create makes a second draft, which cancel
   removes. `depends_on` of the module stays empty, so a tenant without `org` or `locations` gets
   `org_unit_inactive` or `employee_inactive` instead of a crash.

## Org units and the document service

The document service accepts an issuing org unit only when it is in the core scope tree
(`Letflow.ScopeNodePaths`, filled by the org import). An org unit made by another route and not in the
tree makes `issue` answer 422 `request_refused` (the document service refused; the reason is logged by tag only); the draft stays a draft.
