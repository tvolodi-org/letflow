# Stock counts: the count order (REQ-700, GH #3737)

Module `stock` 0.2.0 keeps the **count order** of an inventory taking (decision 0079 sections 1 to 4
and 9). This section stops at the issued order; the cut-off, the book quantities and the count sheet are REQ-701
(section "The count sheet" below), the differences, signing and posting are later. `Counts` itself makes no ledger call.

Every default below is an **assumption, owner may change at GATE B**.

## What exists

| Part | Where |
|---|---|
| Record types `count_order`, `count_order_scope`, `count_commission_member` (module-managed, scoped by the column `org_unit_id`, decision 0076 R7) | `priv/modules/stock/pack.json`, generated by `priv/modules/stock/generate_pack.exs` from `priv/modules/stock/entity_definitions/` |
| Document types `count.order`, `count.sheet`, `count.differences`, `count.posting` (prefixes CO, CS, CD, CP, numbering restarts each year) | registered by `Letflow.Modules.Stock.on_install/3` |
| Functions | `Letflow.Modules.Stock.Counts`: `create/3`, `update/4`, `issue/3`, `cancel/3`, `get/3`, `list/3`, `document/3` |
| Routes under `/api/v1/modules/stock` | `POST /counts`, `PUT /counts/:id`, `POST /counts/:id/issue`, `POST /counts/:id/cancel` (permission `StockCountOrder`); `GET /counts`, `GET /counts/:id`, `GET /counts/:id/document` (permission `StockRead`) |

`StockCountOrder` and `StockCountRecord` (REQ-701) are held by TENANT_ADMIN and PLATFORM_ADMIN only (no role
grants).

## Rules

1. One org unit per order. A scoped caller sees and writes only orders of the org units of their scope;
   any other order, an unknown id and another tenant's id answer the same 404.
2. The chair needs a linked user (`chair_without_user`). Only the chair may cancel (`not_chair`).
3. Issue checks, in order: draft state, active employees and org unit, every root linked to the org unit
   (`count_scope_not_linked`), no root below another root of the order (`count_scope_overlaps`), a
   `full` count covers every location linked to the unit (`count_scope_incomplete`), the period is
   positive and at most 96 hours (`count_too_long`). A refusal stores nothing and takes no number.
4. Two open orders (ordered, counting, counted, signed) of one org unit may not share a location or
   one lie below the other (`count_scope_overlaps`). Issuing takes an advisory lock per tenant and org
   unit first, so two overlapping issues at once give one winner.
5. Cancel works from draft, ordered, counting and counted. The issued document is not touched.
6. Times are stored in UTC; the default tenant time zone Asia/Almaty matters only for the paperwork of
   later slices. "Signed" means a paper signature on the printout; count paperwork in phase B is xlsx
   with signer lines.
7. The routes take no client idempotency key: a retried create makes a second draft, which cancel
   removes. `depends_on` of the module stays empty, so a tenant without `org` or `locations` gets
   `org_unit_inactive` or `employee_inactive` instead of a crash.

## The count sheet (REQ-701, GH #3736; module `stock` 0.4.0)

Every default is an **assumption, owner may change at GATE B**. Functions: `Letflow.Modules.Stock.CountSheet`,
reached as `Counts.open/3`, `record_count/5`, `add_surplus_line/4`, `close_counting/3`, `lines/4`,
`entries/4`, `sheet_document/3`. Record types `count_sheet_line` and `count_entry` (scoped by `org_unit_id`),
permission `StockCountRecord` (TENANT_ADMIN and PLATFORM_ADMIN only).

| Route | Permission | Ok |
|---|---|---|
| `POST /counts/:id/open` (empty body) | `StockCountRecord` | 200 order view with `cut_off_at`, `cutoff_seq` |
| `GET /counts/:id/lines`, `GET /counts/:id/entries` (`limit` 1..200, `cursor`) | `StockRead` | 200 `rows, next_cursor` |
| `PUT /counts/:id/lines/:line_no/count` (body exactly `counted_quantity`) | `StockCountRecord` | 200 line |
| `POST /counts/:id/surplus-lines` | `StockCountRecord` | 201 line |
| `POST /counts/:id/close` (empty body) | `StockCountRecord` | 200 order view with `sheet_document_id` |
| `GET /counts/:id/sheet-document` | `StockRead` | 200 issued summary, no content bytes |

1. **Open**: the chair, an `ordered` count, inside the planned period (`count_not_due`). The cut-off is now.
   Book quantities are read from the stock ledger only through `Ledger.balances/4`: the first read fixes
   `cutoff_seq`, every later page and location is read at `{:event_time, cut_off_at, cutoff_seq}`. One line per
   non-zero balance key of the unit inside the order's locations. A tenant-wide reader opens (a scoped caller or
   an API token gets 404). A ledger refusal is `ledger_read_failed`; more than 2000 lines is `count_too_large`.
   Two concurrent opens give one winner: the loser answers `count_state_invalid`.
2. **Typed input**: the chair or a commission member (`not_commission_member`), a `counting` count. The quantity
   is a decimal string with at most 9 decimals (`field_invalid`); it replaces the counted quantity of the line
   and one entry is appended (`entry_no`, before, after, user, employee, time). Entries are never updated or deleted.
3. **Surplus lines**: a stock item the books do not know. Refusals in order: `location_not_in_count`, `item_inactive`,
   `unit_invalid`, `lot_invalid`, `employee_inactive`, `count_line_exists`. The line has kind `surplus`, book 0.
4. **Close**: the chair, every `stock` line counted (`lines_uncounted` issues nothing and takes no number). The
   `count.sheet` document is created and issued, the order becomes `counted`. Cancel still works afterwards.
5. Every write takes one advisory lock per order first (also `Counts.cancel/3`). Not in this slice: the freeze of
   postings after the cut-off, scanner input and posting (differences and signing: REQ-717, below).

## Signing and the differences sheet (REQ-717, GH #3764; module `stock` 0.6.0)

Every default is an **assumption, owner may change at GATE B**. Functions: `Letflow.Modules.Stock.CountDifferences`,
reached as `Counts.mark_sheet_signed/4`, `issue_differences/3`, `mark_differences_signed/4`, `differences/3`,
`signatures/3`. Record type `count_signature` (append-only, scoped by `org_unit_id`); five optional fields on the
count order (`sheet_signed_at`, `differences_document_id`, `differences_number`, `differences_issued_at`,
`differences_signed_at`). "Signed" is a paper signature on the printout: the chair records it, the system does not
verify it. No ledger call: the posting is REQ-718 and waits for the count freeze.

| Route | Permission | Ok |
|---|---|---|
| `POST /counts/:id/sheet-signatures` (body exactly `signer_employee_ids`) | `StockCountRecord` | 200 order view |
| `POST /counts/:id/differences` (empty body) | `StockCountRecord` | 200 order view with `differences_document_id` |
| `POST /counts/:id/differences-signatures` (body exactly `signer_employee_ids`) | `StockCountRecord` | 200 order view, status `signed` |
| `GET /counts/:id/differences` | `StockRead` | 200 number, version, hash, `lines` |
| `GET /counts/:id/signatures` | `StockRead` | 200 `rows` ordered by `marked_at` |

1. **Sheet signing**: only the chair, a `counted` count. The set must be exact: the chair, every commission member and
   every responsible employee of a sheet line (`signers_incomplete` when one is missing, `field_invalid` for a stranger,
   a duplicate or a malformed id; `sheet_already_signed` on a second mark). The count stays `counted`.
2. **Differences**: needs the signed sheet (`sheet_not_signed`). Built from the issued sheet content, one item per line
   whose counted quantity differs from the book quantity (`difference`, `direction` surplus or shortage). More than 200
   items is `differences_too_many` and takes no number. No difference at all gives an issued document with no `lines`.
   A second issue is `differences_already_issued`.
3. **Differences signing**: the same exact-set rule (responsible employees of the difference lines only); refused
   `count_window_expired` more than 96 hours after the cut-off (the count stays `counted` and can be cancelled). The
   count becomes `signed`, and `Counts.cancel/3` then answers `count_state_invalid`.

## Org units and the document service

The document service accepts an issuing org unit only when it is in the core scope tree
(`Letflow.ScopeNodePaths`, filled by the org import). An org unit made by another route and not in the
tree makes `issue` answer 422 `request_refused` (the document service refused; the reason is logged by tag only); the draft stays a draft.
