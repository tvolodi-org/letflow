# Stock counts: the count order (REQ-700, GH #3737)

Module `stock` 0.2.0 keeps the **count order** of an inventory taking (decision 0079 sections 1 to 4
and 9). This section stops at the issued order; the cut-off, the book quantities and the count sheet are REQ-701
(section "The count sheet" below), the differences, signing and posting are later. `Counts` itself makes no ledger call.

Every default below is an **assumption, owner may change at GATE B**.

grants).

## Rules

1. One org unit per order. A scoped caller sees and writes only orders of the org units of their scope;
   any other order, an unknown id and another tenant's id answer the same 404.
2. The chair needs a linked user (`chair_without_user`). Only the chair may cancel (`not_chair`).
3. Issue checks, in order: draft state, active employees and org unit, every root linked to the org unit
   (`count_scope_not_linked`), no root below another root of the order (`count_scope_overlaps`), a
   `full` count covers every location linked to the unit (`count_scope_incomplete`), the period is
   positive and at most 96 hours (`count_too_long`). A refusal stores nothing and takes no number.
4. Two open orders (ordered, counting, counted, signed) of one org unit may not share a location or
   one lie below the other (`count_scope_overlaps`). Issuing takes an advisory lock per tenant and org
   unit first, so two overlapping issues at once give one winner.
5. Cancel works from draft, ordered, counting and counted. The issued document is not touched.
6. Times are stored in UTC; the default tenant time zone Asia/Almaty matters only for the paperwork of
   later slices. "Signed" means a paper signature on the printout; count paperwork in phase B is xlsx
   with signer lines.
7. The routes take no client idempotency key: a retried create makes a second draft, which cancel
   removes. `depends_on` of the module is `catalog_items`, `codes`, `locations` and `org` (REQ-716 added `codes`):
   a tenant without one of them cannot install `stock`.

## The count sheet (REQ-701, GH #3736; module `stock` 0.4.0)

Every default is an **assumption, owner may change at GATE B**. Functions: `Letflow.Modules.Stock.CountSheet`,
reached as `Counts.open/3`, `record_count/5`, `add_surplus_line/4`, `close_counting/3`, `lines/4`,
`entries/4`, `sheet_document/3`. Record types `count_sheet_line` and `count_entry` (scoped by `org_unit_id`),
permission `StockCountRecord` (TENANT_ADMIN and PLATFORM_ADMIN only).

| Route | Permission | Ok |
|---|---|---|
| `POST /counts/:id/open` (empty body) | `StockCountRecord` | 200 order view with `cut_off_at`, `cutoff_seq` |
| `GET /counts/:id/lines`, `GET /counts/:id/entries` (`limit` 1..200, `cursor`) | `StockRead` | 200 `rows, next_cursor` |
| `PUT /counts/:id/lines/:line_no/count` (body exactly `counted_quantity`) | `StockCountRecord` | 200 line |
| `POST /counts/:id/surplus-lines` | `StockCountRecord` | 201 line |
| `POST /counts/:id/close` (empty body) | `StockCountRecord` | 200 order view with `sheet_document_id` |
| `GET /counts/:id/sheet-document` | `StockRead` | 200 issued summary, no content bytes |
| `POST /counts/:id/scan` (REQ-716; body `scanned_text`, `location_id`, `scan_id`) | `StockCountRecord` | 200 line with `duplicate`, or `kind: location` |

1. **Open**: the chair, an `ordered` count, inside the planned period (`count_not_due`). The cut-off is now.
   Book quantities are read from the stock ledger only through `Ledger.balances/4`: the first read fixes
   `cutoff_seq`, every later page and location is read at `{:event_time, cut_off_at, cutoff_seq}`. One line per
   non-zero balance key of the unit inside the order's locations. A tenant-wide reader opens (a scoped caller or
   an API token gets 404). A ledger refusal is `ledger_read_failed`; more than 2000 lines is `count_too_large`.
   Two concurrent opens give one winner: the loser answers `count_state_invalid`.
2. **Typed input**: the chair or a commission member (`not_commission_member`), a `counting` count. The quantity
   is a decimal string with at most 9 decimals (`field_invalid`); it replaces the counted quantity of the line
   and one entry is appended (`entry_no`, before, after, user, employee, time). Entries are never updated or deleted.
3. **Surplus lines**: a stock item the books do not know. Refusals in order: `location_not_in_count`, `item_inactive`,
   `unit_invalid`, `lot_invalid`, `employee_inactive`, `count_line_exists`. The line has kind `surplus`, book 0.
4. **Close**: the chair, every `stock` line counted (`lines_uncounted` issues nothing and takes no number). The
   `count.sheet` document is created and issued, the order becomes `counted`. Cancel still works afterwards.
5. **Scanner input** (REQ-716, assumptions, owner may change at GATE B): the text goes to `Codes.resolve/2`. An
   item or lot code adds one unit to its single line at `location_id` and appends an entry with `method: scan`;
   a location code in the count answers `kind: location` and records nothing. Refusals: `code_unknown` (404, the
   same body as an unknown count; also a location outside the count), `code_retired`, `code_assignment_conflict`,
   `code_not_assigned`, `code_not_countable`, `location_not_in_count`, `scan_no_line`, `scan_ambiguous`,
   `scan_id_conflict`. A `scan_id` is counted once per order: a retry answers the first quantity with
   `duplicate: true`. Audit action `stock.count.line_scanned` (ids, status, line number only).
6. Every write takes one advisory lock per order first (also `Counts.cancel/3`). Not in this slice: the freeze of
   postings after the cut-off and posting (differences and signing: REQ-717, below).

## Signing and the differences sheet (REQ-717, GH #3764; module `stock` 0.6.0)

Every default is an **assumption, owner may change at GATE B**. Functions: `Letflow.Modules.Stock.CountDifferences`,
reached as `Counts.mark_sheet_signed/4`, `issue_differences/3`, `mark_differences_signed/4`, `differences/3`,
`signatures/3`. Record type `count_signature` (append-only, scoped by `org_unit_id`); five optional fields on the
count order (`sheet_signed_at`, `differences_document_id`, `differences_number`, `differences_issued_at`,
`differences_signed_at`). "Signed" is a paper signature on the printout: the chair records it, the system does not
verify it. No ledger call here: the posting is REQ-718 (next section).

| Route | Permission | Ok |
|---|---|---|
| `POST /counts/:id/sheet-signatures` (body exactly `signer_employee_ids`) | `StockCountRecord` | 200 order view |
| `POST /counts/:id/differences` (empty body) | `StockCountRecord` | 200 order view with `differences_document_id` |
| `POST /counts/:id/differences-signatures` (body exactly `signer_employee_ids`) | `StockCountRecord` | 200 order view, status `signed` |
| `GET /counts/:id/differences` | `StockRead` | 200 number, version, hash, `lines` |
| `GET /counts/:id/signatures` | `StockRead` | 200 `rows` ordered by `marked_at` |

1. **Sheet signing**: only the chair, a `counted` count. The set must be exact: the chair, every commission member and
   every responsible employee of a sheet line (`signers_incomplete` when one is missing, `field_invalid` for a stranger,
   a duplicate or a malformed id; `sheet_already_signed` on a second mark). The count stays `counted`.
2. **Differences**: needs the signed sheet (`sheet_not_signed`). Built from the issued sheet content, one item per line
   whose counted quantity differs from the book quantity (`difference`, `direction` surplus or shortage). More than 200
   items is `differences_too_many` and takes no number. No difference at all gives an issued document with no `lines`.
   A second issue is `differences_already_issued`.
3. **Differences signing**: the same exact-set rule (responsible employees of the difference lines only); refused
   `count_window_expired` more than 96 hours after the cut-off (the count stays `counted` and can be cancelled). The
   count becomes `signed`, and `Counts.cancel/3` then answers `count_state_invalid`.

## Posting a count (REQ-718, GH #3763; module `stock` 0.11.0)

Functions: `Letflow.Modules.Stock.CountPosting`, reached as `Counts.post/3`, `reverse/4`, `issue_posting_record/3`
and `posting_document/3`. The signed differences sheet is posted to the stock ledger as ONE entry (cause
`count_difference`, sign rule `any`, a reason required: `count`), one leg per difference line (a surplus is `+q` at the
`to` side, a shortage `-q` at the `from` side, quantity the absolute difference). It replaces the pair
`count_surplus` / `count_shortage` of decision 0079 section 8: an entry has one cause and a sheet usually has both signs.

**Assumption, owner may change at GATE B (D-086): in the default mode the count freeze is not built** (decision 0079
section 4, split plan row C7; the optional freeze mode is the next section). Stock postings inside the count scope between the cut-off and the posting are NOT blocked.
A difference is therefore posted as a delta (counted minus book at the cut-off, the `difference` of the issued line), so
that a movement made meanwhile stays valid and the balance ends at balance-now plus delta. Known gaps:

1. In the default mode the freeze is not built. Nothing stops a movement during counting.
2. A shortage can exceed the current balance if goods left after the cut-off: the ledger refuses `insufficient_stock`
   when the post task is completed, the task stays pending and the count stays `signed`.
3. A count posted after later movements reports the delta, not "counted = balance".
4. The event time of the entry is `differences_signed_at`; completing the post task more than 96 hours later is refused
   (`event_time_too_old`), with no override (0079 section 8). The same holds for a reversal.
5. The binding of the posting to the issued sheet is by workflow order and detected on read (`posting_check`), not
   enforced, until slice L7 (decision 0078 D5), as for stock documents.

| Route | Permission | Ok | Refusals |
|---|---|---|---|
| `POST /counts/:id/post` (empty body) | `StockPost` | 200 order view, `posting_state` `pending` | 404; 409 `posting_pending`, `count_posted`, `definition_not_active`; 422 `count_state_invalid`, `no_differences` |
| `POST /counts/:id/reverse` (`reason_code`, `reason_text`) | `StockReverse` | 200 order view, `reverse_pending` | 404; 409 `count_not_posted`, `count_reversed`, `reversal_pending`, `posting_inconsistent`, `definition_not_active`; 422 `reason_invalid` |
| `POST /counts/:id/posting-record` (empty body) | `StockCountRecord` | 200 order view, status `posted` | 404; 409 `count_not_posted`, `count_reversed`, `posting_record_exists`; 422 `not_chair`, `count_state_invalid` |
| `GET /counts/:id/posting-document` | `StockRead` | 200 number label, version, time, hash | 404; 422 `count_not_posted` |

Flow: **Post** starts one `stock_count_posting` instance (activated lazily with the caller's own activator) with a
pending `post` task, built only from the issued differences version. Whoever holds the ledger posting authority
(`StockPost`, OIDC credential) completes the task in the task inbox: the entry and one `stock_posting_mark` commit
together. Handlers create records only, so the stored status stays `signed`; the read shows `posting_state` (`none`,
`pending`, `posted`, `reversed`), `entry_id`, `posted_at`, `posted_by` and `posting_check` (`ok`, `mismatch` or null,
never a detail). The chair then issues the **posting record** (`count.posting`: entry id, posting sequence and time,
no quantity) and the status becomes `posted`; this needs the caller's ledger read (otherwise 404). A signed count with no
difference line makes no ledger call: `post` is `no_differences`, the posting record is issued without an entry.
**Rules that stay as they are (P50c, decision 0079):** (1) after a reversal the count cannot be posted again: the
`posted` mark stays, so `post` is refused `count_posted`; order a new count. (2) A `signed` count cannot be cancelled
(`Counts.cancel/3` answers `count_state_invalid`); post and reverse it, or order a new count. The count screen shows both
rules as hints. (3) The read carries `differences_empty` (true only for a `signed` count with no mark and no difference
line): the screen then offers **Issue posting record** at once, which closes the count without an entry. (4) `post` makes
an advisory early check of every shortage line against the CURRENT balance: a shortage larger than the balance answers
422 `shortage_exceeds_balance` with `line_no`, `catalog_item_id` and `location_id` (never a balance), nothing is started,
and the screen names the item and the location. A caller without a ledger read skips the check. Goods that leave after the
post started are still refused by the ledger at task completion (the task stays pending in the inbox).
**Reverse** starts `stock_reversal`; completing its `reverse` task reverses the whole entry and writes a `reversed`
mark; the count documents stay issued. A reversal before the posting record leaves the status `signed` and the record is
then refused `count_reversed`; a count cannot be cancelled from `signed`, so a new count is ordered. Needs the caller's
tenant-wide ledger read, else 404 (fail closed). The posting and the reversal carry `related_document_id` (the
`count.order` document id) and `correlation_id` (the count order record id).

The stock module is installed on no tenant yet; an existing install takes the new pack definition and the three new
optional `count_order` fields through the module-upgrade path (old rows lack them, all reads tolerate that).

## The freeze locations mode (REQ-765, GH #3906; module `stock` 0.17.0)

Owner decision D-094. A count order may carry `freeze_locations` (boolean, an input of create and update, default
`false`, part of the issued `count.order` content). The no-freeze count above stays the default and is unchanged.

* **Start.** `POST /counts/:id/open` of such an order freezes the order's roots and every location below them (taken
  once at the cut-off, stored as `count_freeze_location` rows; a location created later is not frozen). The order gets
  `freeze_started_at` (= `cut_off_at`), `freeze_until` and `freeze_state` `active`; one audit entry
  `stock.count.freeze_started` (ids, number of locations, `freeze_until`; no quantity).
* **Refusal.** While the freeze is in force the stock posting guard (`Letflow.Modules.Stock.FreezeGuard`, the
  `posting_guard` of REQ-764) refuses every posting on a frozen key with `409 location_frozen` and `held_by` the count
  order number (receipt, issue, write off, transfer, hand over and return on either side, opening, and the reversal of
  any of them). A key is frozen by the **pair rule** (decision 0079 section 4): its org unit is the order's org unit AND
  its location is in the frozen set; the same place for another org unit is not frozen. The task stays pending and can be
  completed after the freeze ends. The only exemption is the count's own posting (`count.differences` and the order's
  differences document). Core audits each refusal as `ledger.posting_held`.
* **End.** The state is always computed from the data: `active` until the first of cancel (`ended`/`cancelled`, at once,
  audit `stock.count.freeze_ended`), the `posted` mark of the count (`ended`/`posted`) or the time limit (`expired`).
  The limit is the module setting `count_freeze_limit_minutes` (1 to 5760, default 120, read at the open and stored as
  `freeze_until`; set with `PUT /api/v1/tenant/modules/stock/settings`). An expired count is posted as the plain delta.
  The stored fields (`freeze_state`, `freeze_ended_at`, `freeze_end_reason`) for posted and expired follow lazily at the
  first count write after the end, with one audit entry (`freeze_ended` or `freeze_expired`); a late stored value never
  changes what is refused. A signed order cannot be cancelled, so its freeze ends by posting or by the limit.
* **Reads.** `GET /counts/:id` and the list answer `freeze_locations`, `freeze_state`, `freeze_started_at`,
  `freeze_until`, `freeze_ended_at`, `freeze_end_reason`. `GET /frozen-locations` (`StockRead`; query `location_id`,
  `limit`, `cursor`) lists the frozen locations in force, one row per location and count order with `location_id`,
  `org_unit_id`, `count_order_id`, `count_number`, `freeze_until`, only for org units in the caller's scope.
* **Lock order.** Open takes the order lock, then `Letflow.Ledger.hold_exclusive!/2`, then reads the order and the book
  inside the transaction (see the moduledoc of `FreezeGuard`), so a posting that passed the guard before the open is in
  the sheet and every later one is refused.

Assumptions, owner may change at GATE B: the pair rule rather than the whole place, the refused task stays pending, no
scheduled expiry job, the flag cannot change after issue. Existing installs take the new type and fields through the
module-upgrade path; no row exists before, nothing is backfilled.

## The count worksheet (T-1905; no version bump)

A print of the order for the field, to count on paper and type in later. `GET /api/v1/modules/stock/counts/:id/print/worksheet?lang=ru|kk|en&expected=0|1`
(A4 landscape PDF) and `GET .../counts/:id/paperwork/worksheet` (xlsx); both `StockRead`, the existing `print/:kind` and
`paperwork/:kind` routes with `kind` = `worksheet`.

- **States:** `ordered` and `counting` only (else 422 `worksheet_not_available`). At `counting` the lines are the stored sheet
  lines (including surplus lines); at `ordered` they are a preview computed at print time by the same code the open uses
  (nothing is written; a posting between the print and the open can add or remove a line, the paper says so).
- **Expected quantities:** `expected=0` or no parameter prints the BLANK variant (no expected column, no book quantity
  anywhere). `expected=1` adds the book quantity. No order carries a "blind" mark yet, so `expected=1` is allowed for every
  order the caller may read (the same caller reads `book_quantity` through `GET /counts/:id/lines`); a blind mark would refuse
  it in `CountPaperworkSource.read_worksheet/4`. Any other value is 422 `invalid_expected`.
- **Paper:** header (order number and date, organisation and BIN, org unit, planned start and end, cut-off or book-as-of time),
  commission, lines (No., location, item code and name, lot, unit, [expected], counted, notes) with the header row repeated on
  every page, signature lines, "Page k of N", and on every page a Code 128 of the order number and a QR of the order id.
  The xlsx has no codes (the order number cell is the key).
- **Not a document of record:** no number sequence, no posting, no state change, no audit entry.
- 422 `ledger_read_failed` and `count_too_large` (more than 2000 lines) carry the open's meaning.

## Org units and the document service

The document service accepts an issuing org unit only when it is in the core scope tree
(`Letflow.ScopeNodePaths`, filled by the org import). An org unit made by another route and not in the
tree makes `issue` answer 422 `request_refused` (the document service refused; the reason is logged by tag only); the draft stays a draft.
