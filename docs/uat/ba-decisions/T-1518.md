## Reasons

1. The owner's own gate walks are the strongest source of what matters; items 1 to 3 and 10 come straight from them
   (gate C walkthrough, BA decision `T-1486.md`, and the task text).
2. Items 4 and 5 close a measured gap: the assets scenario folder holds two files for an application with six
   documents, a register and a storekeeper role.
3. Items 6 and 8 protect everything else (stability of the shared queue and tenant isolation); they need no decision.
4. Items already built are not repeated: the G1-G6 chain, the lines editor, voice routes and the friendly names on
   Instances and Home are on main (`git log origin/main`), so the list only adds what is left on top of them.
5. Several "requirement" issues still show `state:ready` on the board although their work is on main (for example
   #3885 REQ-757, #3889 REQ-753, #3899 REQ-762 match merged commits such as #3973). The analyst did not read each
   pull request body; the operator should confirm and close them (see assumptions). They are not candidates.
