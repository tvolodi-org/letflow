# T-1980: decision record for official-form templates (slice S0)

Task T-1980 (no issue number in the task text, so the file is named after the task). The deliverable asked for is the
decision record `docs/migration/decisions/0089-official-form-company-templates.md` (the next free number on origin/main
`dc03badc8`; 0088 is the highest and no team branch adds one). This note records the question, the decision and the reasons.

Decision for UAT only; the process owner configures production.

## Question

Slice S0 of `docs/design/form-template-editor.md` (section 6, row S0): write the decision record for official-form
templates: skeleton and skin, locked placeholders, sanitizer rules, storage, PDF stays the platform layout; amend nothing
in 0068; state the difference to both options 0068 D2 rejected ((b) substitution markers, (c) uploaded file); say how the
template-injection threat T10 of decision 0056 is closed; and carry the amended audit sentence of design section 3.

## Decision

1. A new record 0089, scoped to the forms `FormPrint.forms/0` prints; 0068 and 0056 are not edited (0089 header).
2. Skeleton (platform catalog, locked `legal.*` placeholders) versus skin (the company's Word layout) as design 1.1/1.2
   (0089 D1, D2).
3. Placeholders are bare names against a closed key list; no expressions; values go through `FormPrint.clean/1` and
   `FormPrint.Docx.escape/1` (0089 D2, D3).
4. Sanitizer: one parse, a re-written package from an allow-list, verified bytes only (0089 D4). Two rules are added to the
   design's list: a `<!DOCTYPE`/entity declaration refuses the upload, and `w:dataBinding` refuses it.
5. Storage, versions, rollback, fail closed at print, audit without template content, permission proposal
   `OfficialFormTemplatesManage` (0089 D5); PDF stays the platform layout until S6 (0089 D6).
6. Difference to 0068 D2 (b) and (c), reason by reason (0089 D7); T10 closure for field values, the template and the output
   (0089 D8); the audit sentence (0089 D9) stays as is until S3 and is appended by S5.

## Reasons

* The design (T-1966, on main) already chose option A and argued it against 0068 D2 in its section 2; the record moves that
  argument into the decisions folder, as the design and `docs/uat/ba-decisions/T-1966.md` decision 6 require before code.
* The reasons of 0068 D2 and the T10 text are quoted from the records, not from the design's paraphrase (both opened).
* Every code claim was checked on origin/main: `FormPrint.forms/0`, `FormPrint.clean/1` (invalid UTF-8 gives "", line breaks
  and tabs to spaces, XML-illegal characters dropped, length cap), `FormPrint.Docx.escape/1` (five XML characters),
  `FormPrint.Pdf.blank/0`, `TenantLogo.max_bytes/0` and `validate/2` (scanner seam, fails closed on error or exception),
  `FormPrint.build/4` in `lib/letflow/modules/stock/router.ex`, and in `lib/letflow/api/authorization.ex` the
  `core_role_allows?(:PLATFORM_ADMIN, _permission), do: true` catch-all (with explicit `false` clauses above it only for
  `TasksWorkInScope`, `TenantSecurityManage`, `TasksReassignRouted`) and `core_role_allows?(:TENANT_ADMIN, permission),
  do: permission_scope(permission) == :tenant`. So a new tenant-scope atom is held by TENANT_ADMIN and PLATFORM_ADMIN and
  not granted to any other ready-made role.
* The DOCTYPE rule: OOXML parts never need a DTD, and refusing one removes entity expansion and external-entity reads from
  the parser surface whatever XML library S1 uses (the repo's lock file has `saxy`). The data-binding rule follows from the
  design's own refusal of `customXml/*`.
* 0068 D4 pins an override to an issued 0056 document version; FormPrint forms are rendered on demand and not stored, so
  0089 D5 uses "active at print time" and records the difference instead of copying 0068 D4.
