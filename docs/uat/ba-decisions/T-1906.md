# BA decision T-1906: which official form each stock and asset document prints, and the order of the fixes

The task text has no issue number, so this file is named after the task (T-1906). The full audit is
`docs/status/official-forms-audit.md`.

## Question

The owner's paperwork walk (PM, 2026-11-13): go through every official form of the stock and asset documents. For
each document type, which official Kazakhstan form does it need, does a printout exist, is there a visible print button,
in which languages and formats, what is wrong. Then give a prioritised list of small fix slices, starting with the
warehouse receipt order for receipts and the print buttons on every document screen.

## Decision (for UAT)

1. **Form per document type**: the mapping in the summary table of `docs/status/official-forms-audit.md` is the UAT
   reference. Forms that `docs/assets/kz-forms-mapping.md` already maps (З-1, З-2, З-3, З-5, З-6, З-7, Инв-10, Инв-18,
   ДА-1 to ДА-4, Инв-8, Инв-16) keep that mapping. A receipt prints **З-1 / Қ-1 "Приходный ордер запасов"** (annex 25 of
   order No. 562 of 20 December 2012), which the mapping already lists (sections 3.4 and 8.5) but the product does not
   print.
2. **Forms added by this audit** (the mapping had no row): stock and asset opening, count posting and asset change of
   kind → the accounting certificate А-1 / С-1 "Бухгалтерская справка" (annex 51); the count order → the organisation's
   own free-form order (no annex in order No. 562); asset commissioning → ДА-1 (annex 16). **UAT assumption, to be
   confirmed by the process owner** (and by an accountant).
3. **Order of the fixes** is the slice list of section 4 of the audit: З-1 receipt order first, then the print button on
   every stock document screen (with the Қ-2 label fix), then З-6, then the asset print route and the asset forms. The
   count worksheet is queued separately and the asset count's Инв-8 is already REQ-821; neither is repeated.
4. **Blank, never invented**: every value a form asks for and Letflow does not hold prints as a blank cell or line, as
   the mapping's section 2 default says. No price, VAT, account or signer is filled from a guess.
5. **English**: official forms exist in ru and kk only; an English screen prints the Russian form (current behaviour,
   kept for UAT). The plain acts keep ru, kk and en.

Not decided here (owner): Q19 (hand over and return on З-5), Q21 and Q22 (asset hand over between organisations, which
cost on ДА-4), and whether a tenant may adjust an official form through Print templates (today it cannot).

## Reasons

* The receipt order is a primary accounting document for every receipt of stock (annex 25), and a receipt is the most
  common stock document; with no print at all it is the largest gap the owner can meet on paper.
* A print button on every document screen is cheap (the plain act engine exists for three kinds) and lets the walk
  continue on every document while the official forms are built one by one.
* Slices are one form or one screen family each, so every slice fits one change and carries its own router test and
  browser test, as the З-2 and З-5 builds did.
* Asset prints come after the stock ones because the asset module has no print route yet: the first asset slice is a
  new tenant-data read route and needs a security review, so it is kept small and separate.
