# BA decision T-1832: MES core decisions paper for the owner

(No issue number in the task text, so the file is named by task id.)

## Question
Collect every MES decision that needs a core change or an owner choice before phase 1 (lot status default, customer-transfer marker, one posting guard, shared posting kernel, causes and upgrade run, units and density, hold rule list), with a recommendation, a default and the cost if wrong; list what P2 and P3 changed in the owner paper (08); mark verified vs guess.

## Decision
The answer is `docs/design/mes/12-core-decisions-for-owner.md` (one table of 7 decisions, plus a table of changes to paper 08). Recommendations: backfill old lots as `released` and then treat "no row" as held; a customer-location marker rather than a guard direction; one composed guard; write the kernel decision record before any phase 1 booking; one module version with both new causes upgraded by U1/U2; unit per item with no conversion in phase 1; the P1 hold list as a starting point. Each is a recommendation; the owner decides, and phase 1 stays unauthorized.

## Reasons
- P1 section 6 shows both "no row = released" (unsafe) and "no row = held" (blocks all stock) fail without a backfill, so the backfill is the only safe path.
- P2 and P3 show kg and litres work per item and are never summed, while a litre level cannot give a mass balance without a density; this moves 08's default 5.
- Everything marked [V] is traced to a test ID or code reading stated in docs 09 to 11; the hold rule, effort, density, and the kernel default are guesses and are marked [G].
