# BA decision T-1827: offline install package signing

(No issue number in the task text, so the file is named by task id.)

## Question
Draft the design and test plan for signing offline install packages: hash-only for a controlled pilot, signature before general release, key place as a config setting, dev/test key only (PM, D-121).

## Decision
The answer is `docs/design/offline-package-signing.md` (draft, docs only). Hash-only mode for the pilot (SHA-256 list, manifest hash by a second channel); signed mode (detached Ed25519 signature, offline check with a public key) before general release; key place is a config setting (path or URI), never a value in the repo; steps for key loss, leak, rotation and revoke; a 20-row test plan using a throwaway key made at test time; and a six-part later build task list. Facts, guesses and open questions are labelled.

## Reasons
- The owner said any solution and any convenient key place for now (D-121), so the design keeps the key place behind a setting and decides nothing about the real one.
- A pilot has one known customer, so hash-only needs no key and nothing to lose; the same manifest is later reused for signing.
- Keyless CI signing is compared but not recommended while customers are offline.
