# BA decision T-1836: on-premise delivery of Letflow (MES at a plant's own servers)

(No issue number in the task text, so the file is named by task id.)

## Question
The owner expects on-premise installs at chemical plants and asked whether a mechanism exists. What exists, what is missing, what is the smallest install for one controlled pilot, what comes later, and what differs from our cloud for MES.

## Decision
The answer is `docs/design/on-premise-delivery.md` (design only). Short form: no mechanism exists. For one pilot, build a hand-delivered kit (hash-only package, Docker images for app, Postgres and Keycloak, install script, neutral first-run, backup, upgrade and rollback by package) with our person involved. The hardest gap is sign-in (Keycloak at the plant). Signature, offline upgrade chain, fleet, support access and licence come later. The licence question comes before any package leaves our hands.

## Reasons
- No package, installer, signature or `releases:` config was found in the repo; the signing draft and the T-1519 note say the same.
- Parts exist (Dockerfile, compose shape, backup scripts, platform bootstrap, module upgrade and rollback routes, boot migrations), so the pilot is packaging work, not a new product.
- Keycloak is required at runtime and the repo only runs it in `start-dev`, so identity is the largest risk.
- No LICENSE file exists in the repo, so the owner's "MIT" cannot be confirmed from a source.

## Sources opened
See section 8 of the design (files, greps, and what was not read). The T-1519 note in the sibling repository was opened only through its path and the quotes in the signing draft.

## Assumptions (UAT assumption, to be confirmed by the process owner)
- All effort sizes, server sizes and weeks are guesses, not measured.
- The pilot is a side system, outside any control loop.
- No access by us to the plant by default; the real policy is the owner's choice.
- Licence terms and third-party licence claims are from general knowledge, not checked; legal review needed.

## Conflicts found
The demo runbook says the backend serves the web app; no static-file serving was found in `lib/`, and the QA script swaps a separate bundle. Left as an open question.

Decision for UAT only; the process owner configures production.
