# T-1934: which tests are flaky by design, and in what order to fix them

No issue number was given in the task text, so this file is named after the task id.

## Question

The PM asked on 2026-11-14, after T-1919 (#4444): one sweep over the backend and web tests to find tests that depend on
the real clock or the time of day, on the run order or shared state, or on machine load. The result is a short list
with file, test, why, a one-line fix and a size, most dangerous first. No code changes. The operator queues the fixes.

## Decision

The list is in `docs/status/flaky-test-sweep.md`. It has eight rows, ordered by danger (how often the test can fail
by chance, multiplied by how often it runs in a required check):

1. a time-of-day substring check on a captured log (`ledger_failure_mapping_test.exs`, `refute log =~ "37"`);
2. fixed sleeps before a positive check on asynchronous alert delivery (`obs/alerts_test.exs`);
3. an absolute wall-time ceiling in an async Lua executor test;
4. global `:oidc` config changed inside an async module (`tenant_config_test.exs`);
5. tight elapsed-time ceilings in the lock-timeout tests;
6. year-boundary number assertions (the test reads the year itself);
7. a midnight edge in the shadow-evidence request counts;
8. a substring refute on compressed xlsx bytes.

Items checked and found safe are listed below the table with the reason, so the sweep is not repeated for them.

## Reasons

- Danger order. A check that can fail at any hour (row 1, about 5% per captured log line) comes before one tied to
  load (rows 2 to 5). Those come before ones tied to a calendar instant (rows 6 and 7, only across 00:00 UTC) and a
  check that is weak rather than flaky (row 8).
- The capture_log time prefix was measured, not assumed. On this host, `capture_log(fn -> Logger.error("x") end)`
  returned `"\n06:17:25.414 [error] x\n"`, and `config/test.exs` sets no formatter override.
- A fix that only raises a timeout is not offered without CI evidence (row 5 says so). The product's CI-health rule
  forbids it.
