# T-1846 — Tenant-defined roles: design note (decision for UAT)

No issue number was given in the task text, so this file is named after the task id.

## Question

PM D-129 (owner model): one preinstalled role (platform admin); the owner side creates the tenant admin; the tenant admin creates all other tenant roles and picks their permissions from the list the modules declare. The test case: a tenant stops using `storekeeper`, creates `stockmanager` with the same permissions, replaces storekeeper, and stock, assets, counts and UAT flows work as before. Write the design note, re-verifying the operator's facts against the code.

## Decision

The design note is written: `docs/design/tenant-defined-roles.md` (docs only, no code, nothing on QA, production, demo, secrets, DNS, the public repository or money; MES work not touched).

Decisions taken for the note:
1. Roles become data per tenant: two fixed roles (PLATFORM_ADMIN, TENANT_ADMIN) and seven starter templates (the other seven built-ins) copied into each tenant by a backfill; group membership stays the assignment mechanism (it already exists in `tenant_role`).
2. Permission stays the only thing that decides access; platform-scope permissions are never assignable; nobody can give a permission they do not hold; the last tenant admin always remains; every role change is audited in the same transaction.
3. The operator's facts are all confirmed, and the inventory adds sites the list missed (task-worker scope grants in `tasks.ex`, `routers/tasks.ex`, `scoped_approvers.ex`; `is_task_worker_only?/1`; reassign rule in `tasks.ex`; token issuable role set; role-registry recognised-name rule; `me` access; solution pack role check; UAT schema check; web role lists).
4. Open core: custom roles belong to the open build, so assumption A of T-1842 (nine fixed built-ins, custom roles closed) no longer holds; the first closed features are re-ranked (licence check, audit export and retention, identity provider seam).
5. The asset count spec T-1844 is not on this branch and was not read; the note only states that the signer must be a tenant-chosen permission.

## Reasons

- The code already decides by permission (`role_allows?/2`); what is closed is the name list and the role-to-permission table, so the change is bounded to the resolution of roles and the listed name sites.
- The owner model (one preinstalled role) is a PM decision and is followed as given; where the code contradicts a picture (operator list incomplete) the note says so.
