# BA decision T-1835: MES phase 1 plan

No issue number was given; this file is named by the task id.

## Question
How is MES phase 1 built after the owner's written go of 2026-11-13: tasks in order, which touch the real stock policy, units and conversion, the old-lot backfill, the customer marker, the posting guard, flags, the QA upgrade path, security review points, parallel work, and a draft decision record for the posting kernel?

## Decision
Plan: `docs/design/mes/13-phase1-plan.md` (21 tasks: 18 build in 4 lanes, plus K0 record, X1 ops, X2 UAT). Draft record: `docs/migration/decisions/0087-mes-posting-without-third-copy.md`.
Main points:
1. Only two tasks (S1, then S2) change the real stock module, strictly one at a time.
2. Units: `dimension` on units, physical attributes (density) on items, a conversion table with item-specific and generic rows, a pure converter used on request only; the ledger unit-per-key rule is unchanged.
3. Old lots: the status is a field on the lot and the backfill is one declarative upgrade step (a step cannot insert records); then no status means held, but only while the new setting `lot_hold_enabled` is on. The setting is switched on by installing the MES module.
4. Customer marker: a new optional yes/no field on a location (class A upgrade), not a new enum value (class B).
5. `mes_core` cannot post to the stock ledger from its own handler (a handler's `posts_ledger` must name a registration of the same manifest); proposed: the two handlers live in `stock`.

* `lib/letflow/modules/write_handler_spec.ex` (same-manifest rule); `lib/letflow/modules/step_spec.ex`, `lib/letflow/module_upgrade/step_exec.ex` (steps cannot insert); `lib/letflow/modules/upgrade_plan.ex` (class A optional field, class B changed field); `lib/letflow/module_upgrade/fleet.ex` (never acknowledges); `lib/letflow/modules/catalog_items/catalog_items.ex` (`item_uom_valid?` base unit only; tenant-wide types); `lib/letflow/modules/catalog_items/lots.ex` (`update_lot` allowlist); `priv/modules/locations/pack.json` (`location_type` values); `lib/letflow/modules/stock/stock.ex` (version 0.17.0, settings, ledger map); `lib/letflow/modules/manifest_hash.ex`; `docs/runbooks/demo-upgrade-notes.md` (demo promote runs the chain).
* Owner answers of 2026-11-13 in the task text; docs 05, 07, 09, 10, 11, 12; `docs/design/core-extraction-design.md` sections 1, 3, 6, 7.

## Assumptions (UAT assumption, to be confirmed by the process owner, or by the task named in the plan)
* The decision record is in `docs/migration/decisions/` because `docs/decisions/` does not exist and all earlier records live there.
* Conversion path cap of 3 rows, rounding half up at 9 decimals; the hold rule list from doc 12; sizes and weeks.
* A `mes_core` process may call a `stock` handler; `catalog_items` may take the stock exclusive hold; the backfill step skips lots that already have a status; class A for a new entity type. Each is a guess checked by a named task, and the plan says what to do if it fails.
