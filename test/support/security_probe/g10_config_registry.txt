# letflow config/env/flag registry
# format: 1
# columns: source name owner scope read kind default fail_closed validator reason
#
# Every environment variable and every application environment key the tree names has one line
# here: a setting the sources read, and a variable the sources name to neutralise it for a
# child process (the git settings of lib/letflow/risk_tier.ex). The probe of gap G-10
# (test/letflow/security_probe/g10_config_registry_test.exs) derives the other half from the
# tree and fails until the two agree, so a new setting cannot be added without saying who owns
# it, why it exists, how it is read and whether its absence must fail closed.
#
# source      env (an operating system variable) or app_env (an application environment key)
# name        the variable name, or the application key as `app:key`
# owner       the area that owns the setting and answers for it
# scope       platform (the whole deployment), module (one module), tenant (one tenant) or test
# read        runtime (read when it is used) or compile_time (read while the code is compiled)
# kind        plain, flag (a feature switch, off by default), guard (a safety switch, on by
#             default), secret (a credential, by reference only) or url (an address)
# default     none (the setting has no default), false, true, a number, or module (the owning
#             module's own constant)
# fail_closed yes when the absence of the setting must not take effect
# validator   none (no tenant-controlled outbound fetch of the address: the operator
#             sets it and no tenant can point it elsewhere) or the module of the tree
#             that validates it
# reason      one plain sentence: why the setting exists
#
# A reason must not end in a question mark and must not be a placeholder. A refresh is not a
# way to bypass a finding: a reviewer accounts for every added, removed or changed line.
