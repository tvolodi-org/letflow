# GH-2891 -- R8 whole-file YAML parse guard

Defect: `docs/requirements.yaml` on main did not parse (REQ-519 AC 24: unescaped inner
double quotes in a double-quoted scalar). CI stayed green because every check scans
lines and none parses. Fix: re-quoted line + R8 (`parse_check/1`, wired into `run/1`).

Tests: `test/mix/tasks/letflow_check_requirements_registration_test.exs`,
describe "R8 -- whole-file YAML parse guard (GH #2891)".

| Criterion | Test | Why it exists |
|---|---|---|
| Valid document accepted | R8-VALID | Guards against a guard that rejects everything. |
| The real defect shape is rejected | R8-BROKEN | Reproduces the exact failure; also asserts `scan/2` reports no violation on the same bytes, proving the gap only R8 closes. |
| The fix shape is accepted | R8-FIXED-SHAPE | Same text with single-quoted inner quotes passes; pins the remedy. |
| Parser failures never propagate | R8-NEVER-RAISES | Two garbage inputs must give `{:error, binary}` (the catch clause). |
| The live file parses (fix of the line itself) | T-LIVE-PARSE | Fails if the bad quote on REQ-519 AC 24 (or any other) returns. |

`run/1` integration is not tested: it reads a fixed relative path (same constraint as
T-TASK-* in this file).

2. `parse_check/1` returns `{:error, _}` on valid input -- expected killed by R8-VALID,
   R8-FIXED-SHAPE, T-LIVE-PARSE.
3. Re-introduce the bad quoting on the REQ-519 AC 24 line of `docs/requirements.yaml`
   (around line 36939) -- expected killed by T-LIVE-PARSE.
