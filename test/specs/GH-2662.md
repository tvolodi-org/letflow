# Test spec: GH #2662 / REQ-506 (org behaviour, read API, isolation, limits runbook)

All tests are integration tests on real Postgres with real provisioned tenants and the real
installed `org` module (no mocks). Shared fixture: `test/support/modules/org_fixture.ex`
(`Letflow.OrgFixture`). Owner path: `Records.create_record/update_record/delete_record` `/3` with
`ManagedTypes.owner_for!(Letflow.Modules.Org)`.

Files: `test/letflow/modules/org/behaviour_test.exs` (AC1-3), `read_api_test.exs` (AC4, AC5),
`runbook_test.exs` (AC6).

## Acceptance criteria to tests

| AC | Test | Why it exists |
|---|---|---|
| AC1 uniqueness | behaviour: `U-org_legal_entity`, `U-org_site`, `U-org_unit` | The DB constraint (not an app check) refuses a duplicate `code`; asserts rule `:unique` and path `["code"]` (the mapping in `records.ex`), and that a different code is accepted so the refusal is about the code. |
| AC1 (extra) | behaviour: `U-membership` | The composite pair constraint `uq_org_unit_membership`; path is both fields; the same user in another unit is allowed. |
| AC2 idempotency | behaviour: `D-01` | Same key + payload: `is_duplicate` true, same `record_id`, same `last_event_global_seq` (no second event). |
| AC2 | behaviour: `D-03` | Same actor and key, different payload: `:idempotency_key_reuse`. Isolates the payload comparison in `same_request?` (D-02 differs in actor too). |
| AC2 | behaviour: `D-04` | Same key and payload, different actor: `:idempotency_key_reuse` (`match_original/3` compares the actor before the payload). Isolates the actor comparison. |
| AC2 | behaviour: `D-02` | Same key + different payload: `{:error, :idempotency_key_reuse}`; the refused payload is not stored (its code is still free). |
| AC3 concurrency | behaviour: `C-01` | Update with the current `last_event_global_seq` succeeds and advances it. |
| AC3 | behaviour: `C-02` | Stale value: `:record_version_conflict`, and the record keeps the winner's value. |
| AC3 | behaviour: `C-03` | Delete with stale value refused (record still readable); with the current value it succeeds (throwaway record). |
| AC4 read API | read_api: `R-<type>` x4 | `lookup` returns `record_id`, `entity_type` and every field value; `active?` true. |
| AC4 | read_api: `R-<type>-inactive` x4 | `active: false` is found but `active?` false. |
| AC4 | read_api: `R-<type>-deleted` x4 | Soft-deleted record: `{:error, :not_found}` and `active?` false. |
| AC4 | read_api: `R-unknown`, `R-nonuuid`, `R-nonbinary-prefix` | Unknown uuid, and nil/123/"x"/""/map/list/atom/float/invalid utf-8 never raise. |
| AC4 member? | read_api: `M-01`..`M-07` | Truth table: active+active true; inactive membership false; inactive unit false; unknown and deleted unit false; other user / other unit false; deleted membership false; non-uuid unit and non-text user never raise. |
| Hostile input | read_api: `H-01` | NUL, invalid UTF-8, >256 bytes, "" give false without raising for an existing active unit (no membership rows exist for them, so H-01 proves never-raise, NOT the cap value). |
| Hostile input | read_api: `H-02` | Memberships EXIST (Owner path) for a 256-byte and a 257-byte user_id: member? true for 256, false for 257. This is the only test that observes the cap value. |
| AC5 isolation | read_api: `T-01` | Two tenants; B's prefix returns nothing of A's records for lookup, active?, member?; the same code in B is an independent record. |
| AC6 runbook | runbook: `B-01`..`B-06` | Heading, numbered 1..N list, each limit cites a GH number or a code path, GH refs are plain numbers, every cited path exists with cited lines in range, and the cited lines still hold the named symbol (stale-line detector). No network. |

AC7 (SECURITY/REVIEWER verdicts) and AC8 (compile/format/boundaries) are not test-designer scope.

## Mutants for TEST-DESIGN-VALIDATOR (NOT applied by the designer)

Apply one at a time to `lib/letflow/modules/org/org.ex`, run the three org test files, revert.

1. `member?`: drop `{:ok, %{"active" => true}} <- unit_by_id(...)` check (accept any unit). Expected kills: `M-03`, `M-04` (deleted unit still gives false through unit_by_id, so mainly `M-03`).
2. `active_membership?`: remove `fragment("?->>'active' = 'true'" ...)`. Expected kill: `M-02`.
3. `active_membership?`: remove `not r.deleted`. Expected kill: `M-06`.
4. `active?`: replace with `match?({:ok, _}, lookup(prefix, id))`. Expected kills: every `R-<type>-inactive` (4).
5. `safe_text?`: drop the `String.valid?` clause. Expected kill: `H-01` (Postgres raises on invalid UTF-8).
6a. `safe_text?`: drop the NUL check. Expected kill: `H-01`.
6b. `safe_text?`: change `<= 256` to `<= 100_000`. Killed by `H-02` only (verified: `Result: 24/25 passed`); H-01 does not kill it.
7. `lookup`: replace `Ecto.UUID.cast(id)` with a pass-through so a non-uuid reaches the query. Expected kill: `R-nonuuid`.
8. `first_live`/`@types`: remove `"org_unit_membership"` from `@types`. Expected kill: `R-org_unit_membership`.
9. `to_map`: drop `"entity_type"` from the merge. Expected kills: all four `R-<type>`.
10. `lookup`: ignore `prefix` (use a hard-coded tenant). Expected kill: `T-01`.

Runbook mutants: remove "(`lib/letflow/modules/org/org.ex`)" from limit 6 (kills `B-03`, observed on the
checkout before the fix); shift `records.ex:1004` to `:1005` (kills `B-06`).

Behaviour tests (AC1-3) exercise core `Records`, which is unchanged in this requirement; they
pin the contract the org module relies on, so a mutant in `records.ex` (e.g. dropping the
`:unique_violation` mapping) is the relevant one: it kills `U-*`.
