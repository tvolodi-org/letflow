# ISS-1043 test spec: `GET /health` reports the build SHA

Issue: `docs/issues/ISS-1043.yaml` (GH #2384). Test file: `test/letflow/iss1043_health_build_sha_test.exs`
(`async: false`: it writes `:build_sha` into the application env and `LETFLOW_BUILD_SHA` into the OS env, restoring both).
Updated: `test/letflow/router_test.exs` (3 assertions) and `test/letflow/plugs/cors_test.exs` (3 assertions), whose exact
`/health` body is now `%{"status" => "ok", "sha" => Letflow.BuildInfo.sha()}`.

Chain: `deploy/redeploy-{qa,test}.sh` `--build-arg GIT_SHA="$(git rev-parse HEAD)"` -> `deploy/Dockerfile` runtime stage
`ARG GIT_SHA=` / `ENV LETFLOW_BUILD_SHA=${GIT_SHA}` -> `config/runtime.exs`
`config :letflow, :build_sha, Letflow.BuildInfo.normalize_sha(System.get_env("LETFLOW_BUILD_SHA"))` -> `GET /health`
`%{status: "ok", sha: Letflow.BuildInfo.sha()}`.

Normalisation rule (`Letflow.BuildInfo.normalize_sha/1`): trim surrounding whitespace, then keep the value only if it is
7..40 lowercase hex characters; everything else (nil, empty, uppercase, too short/long, non-hex, embedded whitespace,
non-binary) is `nil`. `sha/0` re-normalises the app-env value on read.

## Criterion to test mapping

| Acceptance criterion | Test | Why |
|---|---|---|
| Public unauthenticated route returns the SHA baked into the release | `sha is the configured build SHA, status is still exactly ok, no other key`; `a short (7-hex) SHA is reported as configured`; runtime-config tests `a valid SHA is stored as is`, `unset, empty and junk values are stored as nil` (real `Config.Reader.read!` of `config/runtime.exs` with `LETFLOW_BUILD_SHA` set) | Proves env var -> app env -> response, not just the router |
| No tenant data, no token (outside AuthPipeline like /health) | Same router tests call `Letflow.Router` with no auth header and no sandbox checkout; body keys asserted to be exactly `["sha", "status"]` | Nothing else can leak into the public body |
| `status` stays "ok" | Every /health test asserts `"status" => "ok"`; updated router_test/cors_test assertions | redeploy-*.sh health checks read `.status` only |
| SHA is injected at build time | Static: `deploy/Dockerfile declares ARG GIT_SHA and ENV LETFLOW_BUILD_SHA in the runtime stage` (in the last stage, ARG before ENV, after every apt-get line); `deploy/redeploy-qa.sh` / `deploy/redeploy-test.sh passes the full HEAD SHA as --build-arg GIT_SHA` (every `docker build` line, no `--short`) | The SHA has to reach the image, not only the app |
| Preflight reports deployed_sha OK after a QA redeploy | Static: `scripts/uat_preflight.sh probes /health and accepts the sha key`. The live QA result is NOT verified here: it needs a real QA redeploy | Preflight needs no change; real confirmation is post-deploy |
| Unset / malformed values | `sha is JSON null when no build SHA is configured`; `sha is JSON null when the app env holds a malformed value`; `normalize_sha/1` accept/trim/reject tests; 4 doctests | null, not a dropped key or a junk string |
