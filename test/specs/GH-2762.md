## Notes

1. **T-59d is deterministic and needs no seed.** Its pool size equals the rule count, so the one deleted question is
   in the pool on the old code in every run and is drawn every time; the fixed code answers `:pool_underflow`. It
   stays in the GH-2759 spec; it is mentioned here because the same "count == pool size means always drawn" device
   is what makes T-62n deterministic. T-62m is the only seed-dependent test; it is deterministic per seed, asserts on
   BOTH outcomes across 30 fixed seeds (each misses the broken question with probability 1/3, so the chance of a
   spurious "no seed succeeded" is (2/3)^30), and every individual assertion is per seed.
2. **T-62l second half and T-62h2 are the only RED proofs of the display claim.** The first half of T-62l and the
   "kept" behaviour pin design 4.2 (mid-exam display unchanged): `build_option_states/4` is NOT changed, and a mutant
   that filters inside it fails the first half.
3. **No wall clock, no unseeded randomness.** Sessions are started with `Session.create_with_seed/4` wherever the
   draw matters (T-62a..c use a one-question pool, so the draw is moot).
4. **Not tested:** the promoted per-type table path for `answer_option` (the fixture never promotes a column, same as
   the #2734 spec Observation 3).
