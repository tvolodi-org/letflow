# Test Spec: GH #2760 -- a soft-deleted exam must not start a session and is not offered

**Issue:** GH #2760. Binding design (RULED): `lib/letflow/design/gh2762-exam-soft-deleted-reads.md`, section 3.1 and
test rows T-60a..T-60f. Implementation: `lock_exam_row/2` gains `r.deleted == false` in its locked WHERE and
`list_available_exams/2` gains `deleted eq false` (`lib/letflow/modules/exam/session.ex`, commit 027df801).

**Test tier:** integration against real Postgres and real provisioned tenants (DIRECTIVE T-1); no mocks.

**Files:** `test/letflow/modules/exam/session_test.exs` (describes "GH #2760 -- soft-deleted exam on the START path" and
"GH #2760 -- list_available_exams/2 ..."), `test/letflow/modules/exam/exam_sessions_test.exs` (describe "GH #2760 -- HTTP
start on a soft-deleted exam").

Legend: RED = fails on main c309227b (main's `lock_exam_row/2` and the available-exams filter list have no `deleted`
predicate, so a deleted active exam is locked, passes `check_exam_status/1` and is listed); this is derived from the
diff `c309227b..HEAD -- lib`, not from running main. GUARD = passes on main and pins behaviour that must not regress.

## Not tested: the delete-while-waiting race

A start that is blocked on the exam row's `FOR UPDATE` lock while a delete commits cannot be produced
deterministically: `Letflow.DataCase` runs these suites on one shared sandbox connection, on which two processes' row
locks never block each other. A non-deterministic race test was rejected on purpose. The locked-WHERE predicate that
the race depends on is the same predicate T-60a/T-60a2/T-60c exercise.

## Mutants (design section 7), for the validator to apply

* Remove `deleted == false` from `lock_exam_row/2`: T-60a, T-60a2, T-60c, T-60b must fail.
* Drop the `deleted` filter from `list_available_exams/2`: T-60f, T-60b2 must fail.
* Return a distinct atom for a deleted exam: T-60a2, T-60b, T-60c must fail.
* Filter on everything (e.g. `deleted == true` inverted): T-60d, T-60f2 must fail.
