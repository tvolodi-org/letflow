## Deviations from the design text (recorded, not re-decided)

- T-G1: design 12.6 says "with a second admin (member or TA token owner) -> 200". A second TA
  MEMBER cannot keep the count above 0 when the TA binding itself becomes a routing role (every
  member-admin goes at once), so two members -> 409 and only a TA token owner -> 200.
- T-F9: a raising audit trigger is caught by `flip/4`'s rescue, so the function returns
  `{:transaction_failed, %Postgrex.Error{}}` (the design's `{:audit_failed, _}` is the non-raising
  form); both answer 500 and the mode is unchanged.
- T-F2: there is no tenant_config WRITE route (`/api/tenant-config` is a public GET); the T-F7
  changeset pin covers it.
- T-RW4b: `TenantProvisioning.ensure_column_promotions/2` does not exist; the test provisions a
  second tenant and asserts the managed types and grant rows are unchanged.
- T-RW2: every route is walked with an empty body; valid bodies only for the named identity,
  onboarding and scope-enforcement routes (POST /onboarding excluded: it provisions a tenant).
- T-S1: a fixed list of 8 GET routes (at least 3 must answer 200), not one per router.
