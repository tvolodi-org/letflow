# Test spec -- REQ-464 (validator checks for `distinct_from`: shape, existence, path position, single-member-role warning)

**Requirement:** REQ-464 (S3; source GH #2323 / ISS-1034, queue Q-1027, GH #2342).
**Author:** TEST-DESIGNER. **Design read:** `lib/letflow/design/req459-required-outputs-and-distinct-person.md`
sections 1.1, 1.2 (reserved codes), 1.5 (relation table), Adjustments REQ-464, OQ-2, plus implementation commit
`7befe9f9` (`graph.ex` CHK-26/CHK-27, `role_binding.ex`, `validation_warnings.ex`).

**Requirement text (summary):** `distinct_from` on a HUMAN_TASK is a duplicate-free list of non-empty node ids that are
HUMAN_TASKs of the same definition, never the node's own id, and never a node reachable only AFTER this node (a
preceding, parallel, mutually exclusive or rework-loop node passes; BA 2026-10-07). On any other node type the attribute
is a violation. Plus a WARNING (never a violation) `distinct_from_single_member_role:` when this node and a listed node
route to the same `attributes["role"]` and that role has exactly one member in the installing tenant; evaluated at pack
install and `validate_definition_graph/2` / `POST /definitions/:id/validate`, not at activate. Reserved codes:
`:invalid_distinct_from`, `:distinct_from_on_non_human_task`, `:distinct_from_self_reference`,
`:distinct_from_unknown_node`, `:distinct_from_not_human_task`, `:distinct_from_downstream_only`.

## Design vs requirement differences

None that change a test. Implementation note only: the design names `build_adjacency/2` for reachability; the code uses
`flow_adjacency/3` + `walk/2` (same resolved-edge forward closure). Tests assert behaviour, not the helper.

* Message prose beyond the fragments the design reserves (node id, listed id, `reachable only after`, `duplicate`, the wire text of the warning).
