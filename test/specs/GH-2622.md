# GH #2622: per-sha CI concurrency for main pushes; CD deploys the tested tip when QA differs; one path-rule source; job timeouts

Ruling: issue #2622 "Ruling change" R1-R6 (REQ-367's CD path gate dropped; fail-closed decision; timeouts; fork-branch `workflow_run` hole; OQ-1 race reading). Design: `lib/letflow/design/gh2622-ci-push-concurrency-and-cd-tip.md` (rev 3). Code: `.github/workflows/ci.yml` (concurrency group, job `changes` step "Compute changed paths", artifact steps removed), `.github/workflows/cd.yml` (rewritten: jobs `deploy` and `skip-log`), `scripts/ci_changed_paths.sh` (new), `scripts/cd_qa_decide.sh` (new), `docs/runbooks/qa-lag.md` (new).

## Behaviour under test
CI: a push to `main` gets the concurrency group `CI-refs/heads/main-<sha>`, so no push run is queued behind or cancelled by another; `pull_request` (per PR, cancel in progress) and `merge_group` (`github.ref`) are unchanged. The path rules (`BACKEND_PATHS_RE`, `FRONTEND_PATHS_RE`, `MOBILE_PATHS_RE`) live only in `scripts/ci_changed_paths.sh`, which reads all of stdin and prints exactly `backend=`, `frontend=`, `mobile=` `true|false`. The `changes` job feeds it the diff, accepts its output only when the exit is 0 and the three lines are well formed with distinct keys, and otherwise exits 1 so the fail-safe step runs every gate. Event fields reach that step through `env:`. Nothing is uploaded for CD.

CD: job `deploy` runs only for a successful CI `push` run from this repository (the fork-branch-`main` hole, R5), in job-level group `cd-qa` (never cancelling in progress), read-only token, checkout of `main` without persisted credentials. Step `inputs` reads the tip (API, then `git fetch`, then `origin/main`, re-read once on mismatch), the tip's CI push run, and `/health` into a file. Step `decide` runs `scripts/cd_qa_decide.sh` (9-row table; rows 1-3 red, row 4 skip, rows 5-9 decided by the health signal), validates its two lines, logs the `cd-qa:` reason, and is red on a red decision or malformed output. The SSH step (inputs byte-identical to before) runs only on `deploy == 'true'`. The verify step fetches, resolves QA's sha, and requires it to be the tip or a descendant. Job `skip-log` runs exactly when `deploy` is skipped by its `if:` and prints `cd-qa: skipped (...)`.

Files: `F` = `test/letflow/ci_backend_path_filter_test.exs` (retargeted), `C` = `test/letflow/gh2622_ci_push_concurrency_test.exs`, `D` = `test/letflow/gh2622_cd_qa_tip_rule_test.exs`, `S` = `test/scripts/cd_qa_decide_test.exs`, `T` = `test/letflow/gh2622_ci_cd_timeouts_test.exs`.
