## Fail-first evidence

The code under test did not exist before this requirement, so "fails against pre-change code" is trivially true and is
therefore NOT the evidence relied on. It is reported anyway (throwaway worktree at the merge-base `5b56822a`, a fresh
partition DB without the new column): 54 of 58 tests fail there (SCH fails to compile: the struct has no such key).
The 4 that pass there are regression guards of unchanged behaviour: the default / unknown-realm responses carry no mode
bytes; nil actor on a display_name-only patch succeeds; an unprovisioned tenant's display_name patch succeeds; an unknown
extra body key is still dropped. The exposure tests (EX) fail there only because their setup writes the new column, so
they prove nothing about leakage on their own -- hence the mutation evidence below.

The evidence relied on is MUTATION, each mutant reverted and the revert verified with `git status --short lib priv` (empty):

| Mutant (shipped logic changed) | Test file run | Result |
|---|---|---|
| M1 `login_directory.ex`: `? AND COALESCE(...)` -> `? OR COALESCE(...)` (ceiling broken) | LD | 7 of 21 fail (both ceiling cells, the (redirect_single, uniform) cell, both junk-deployment tests, both multi-tenant tests) |
| M2 `identity.ex`: audit `after_state` also carries the mode | RT | 3 of 24 fail (both per-mode audit tests, the GET /audit byte-level test) |
| M3 `identity.ex`: nil-actor guard removed (`with true <- true`) | RT | 2 of 24 fail (nil-actor 500, patch_tenant/3 contract) |
