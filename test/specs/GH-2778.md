# GH-2778 test spec: DELETE attachment with a malformed instance id

Code under test: `handle_delete_attachment` in `lib/letflow/routers/instances.ex`. On main its
`with ... else` has no `{:error, :invalid_instance_id}` clause, so `cast_instance_id/1` returning
that error raises `WithClauseError` (500). The fix adds the clause returning
`Response.unprocessable(conn, "instance_id is not a valid UUID")`, as the five sibling handlers do.

Tests: `test/letflow/routers/gh2778_attachment_malformed_id_test.exs` (real HTTP via `Letflow.Router`).

| Acceptance criterion | Test | Label | Why it exists |
|---|---|---|---|
| DELETE malformed id returns sibling status and body | DELETE answers 422 with the byte-identical body of the sibling routes | RED | Main has no clause for DELETE: 500, not 422. Byte equality with the download route pins "same as siblings", not only a status. |
| (same) | DELETE: the 422 is independent of the attachment id | RED | The error must come from the instance id alone. |
| (same) | all six handlers return the identical 422 body | RED | Fails on main only through the DELETE member; guards that no handler drifts from the shared body. |
| A test per handler sends a malformed id | upload / list / download / issue link / link-content | GUARD | These five already have the clause and pass on main; they stop a future clause regression. |
| (no oracle) | caller without permission gets the plug 403 for a malformed id, equal to a valid-shaped id, on all six routes | GUARD | Permission is checked before id parsing; passes on main and after the fix. Pins that the new clause did not move id parsing ahead of the permission check. |

The RED/GUARD split comes from reading the diff (only DELETE lacked the clause), not from running
the tests against main.
