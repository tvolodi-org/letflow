## KNOWN residuals (accepted)

- Cost: a non-operator list request that hides rows scans the tenant's `promotion_reviews` by keyset in chunks of
  `max(page_size + 1, 100)` full rows (the `serialised_plan` text is loaded and JSON-decoded per scanned row; the page items need
  the row anyway). No cap by design (a cap forces a cursor on a hidden row or strands visible rows). Remedy if it ever matters: a
  stored visibility column written at insert (separate issue). Timing is not byte-observable; flagged for SECURITY-REVIEWER (R2/R3/R7).
- A review the caller created as an operator in its own schema naming foreign tenants becomes invisible to that caller once it
  is no longer an operator (intended; same as approve/reject/apply).
- Pre-existing red, unrelated and unchanged by this fix (they fail identically on e29356eb8):
  `tenant_admin_routes_test.exs` "AC2: a TENANT_ADMIN of an ordinary tenant is allowed (2xx), router by router" (POST
  /identity/users answers 500) and `req077_promotion_pipeline_test.exs:1279` "design 12.9 ... POST /promotions/plan with a
  real VIEWER token" (500 instead of 403).
