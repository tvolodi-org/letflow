## Behaviour (final)

| Caller | `GET /:id/context` | `GET /:id` | `GET /` |
|---|---|---|---|
| operator (`PLATFORM_ADMIN` of the pinned P) | 200; an unparseable stored plan renders `serialised_plan: null` (tolerant decode), never a 500 | 200 | unfiltered (unreadable rows included) |
| named party, both ids own (`:full`) | 200, today's view | 200, existing 7-key run map | row listed |
| named party, one id own (`:own_side`, source OR target) | 200, ISS-1023 own-side view (foreign ids omitted, `entries: []`) | 200, the SAME existing 7-key run map (no new shape) | row listed |
| non-party non-operator (neither id own, or ids unreadable / absent / non-string, plan not a JSON object) | the nonexistent-id 404, byte for byte (status, headers, body) | same | row omitted, no placeholder, no count, no cursor on a hidden row |

The party is decided ONLY from the stored ids vs the authenticated `auth_context.tenant_id` (never a query param, header or
body). AC1 and the literal AC5 sentence pull in different directions (the 7-key run map can carry free-text
`teardown_error` / `failing_assertion_ids`, a PRE-EXISTING property); AC1 was preferred and the residual is left to
SECURITY-REVIEWER and a follow-up issue.

Setup (route tests in `test/letflow/routers/promotion_read_stored_ids_test.exs`, `async: false`): three provisioned tenants,
pin on P. The non-operator reader is `TENANT_ADMIN` of A (or of P with the pin on or unset); the operator is `PLATFORM_ADMIN`
of the pinned P. The baseline for every denial is `Scope.observable/1` of the same call for a nonexistent review id. List order
is pinned by writing `inserted_at` explicitly (`seed_ordered!/3` kinds `:own`, `:hidden` = non-party (f1 -> f2),
`:party_src`, `:party_tgt`, `{:raw, text}`).

## KNOWN residuals (accepted)

- Cost: a non-operator list request that hides rows scans the tenant's `promotion_reviews` by keyset in chunks of
  `max(page_size + 1, 100)` full rows (the `serialised_plan` text is loaded and JSON-decoded per scanned row). No cap by design
  (a cap forces a cursor on a hidden row or strands visible rows). Remedy if it ever matters: a stored visibility column written
  at insert (separate issue). Timing is not byte-observable; flagged for SECURITY-REVIEWER.
- The 7-key run map returned to a party carries free-text `teardown_error` / `failing_assertion_ids`, which can in principle
  name the foreign side of a review with a foreign counterpart. Pre-existing, unchanged by this issue; follow-up issue to be
  filed (status-only or allowlisted run map for parties).
- A party still sees `def_id`, `process_key` and `requested_by` of a review naming a foreign counterpart (ISS-1023 R4/R8, unchanged).
- A review the caller created as an operator in its own schema naming only foreign tenants becomes invisible to that caller once
  it is no longer an operator (intended; the same review is refused on approve/reject/apply).
- Pre-existing red, unrelated and unchanged by this fix: `tenant_admin_routes_test.exs` "AC2: a TENANT_ADMIN of an ordinary
  tenant is allowed (2xx), router by router" (POST /identity/users answers 500) and `req077_promotion_pipeline_test.exs:1279`
  "design 12.9 ... POST /promotions/plan with a real VIEWER token" (500 instead of 403).
