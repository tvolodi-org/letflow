## Observations

1. **T-50c5 (c) is not red on main.** The fixture is nil weight plus `is_correct: true`. On main that deleted
   option is read as live, and its nil weight already makes `build_likert` refuse `{:key_missing, id}`, the same
   value the fixed code returns for the deleted key-bearing option. The design table lists it as red; it cannot be,
   since isolating `is_correct` as the only key-bearing signal requires a nil weight. It is still a real test: it is
   killed by the mutant that drops the `is_correct` clause of the likert `key_bearing?/2` (the option would then be
   excluded and the snapshot built). Reported as a guard with a killable mutant, not a red test.
2. **T-50c2 under "treat every deleted option as excluded".** Design section 6's mutation row lists T-50c2 as killed
   by that mutant. With a single-choice question whose only correct option is deleted, excluding it still leaves no
   correct option, so `check_key/3` refuses with the same `{:key_missing, id}`: T-50c2 passes under that mutant.
   T-50c3 (multiple, another correct option stays live) and T-50c5 (a) / (c) / T-50c6 do kill it. T-50c2b (truefalse, two options) passes under it too, for the same reason as T-50c2.
3. **OQ-7 (promoted per-type table path): not exercised.** `Letflow.ExamFixtures` deliberately never promotes a
   column or creates a per-type table (its tenants delete the `entity_column_promotions` rows, see the ISS-0648
   notes in `test/support/exam_fixtures.ex`; the fixture definitions drop `fk_def` entries), so every exam entity
   type here resolves to the `:latest` binding, which is the path T-50c*, T-50d and the `eq "deleted"` filter run
   on. The `eq` on `"deleted"` filter is also covered on that path by `test/letflow/entities/query_test.exs:511-515`.
   Building a promoted exam tenant would need a column-promotion harness this change does not own; the builder's
   defence for a misbehaving promoted path (post-filter on the selected `deleted` field) is not exercised.
4. Tests that need a started session with extra options create them AFTER the session started (shorttext option,
   likert third option): the late build reads live rows, and the start snapshot used for comparison is read before
   any deletion.
