## AC -> tests

### AC1: every path that grants or removes TENANT_ADMIN writes an audit event (actor, target user, before/after, UTC time, trace id); one test per path

Each path test asserts the event name, `actor_id`, `resource_id` (target user, or the role for a
binding), `trace_id`, the full `before_state`/`after_state` and `Audit.verify_chain/1 == {:ok, :valid}`.
UTC time is stamped by `Audit.insert_entry/3` itself (no path sets it; the rebind suite already pins it).

## Fixture change to an existing test

`test/letflow/identity/pending_admin_binding_test.exs`, the two concurrent-binder tests: the bind now
takes the tenant admin advisory lock before the grant row, so the second binder waits on the
advisory lock, not on the grant row `FOR UPDATE`, and `PendingAdminHelper.lock_waiters?/3` (row
waiters only) can never see 2. Replaced at both call sites by a local `binders_blocked?/1` that counts
row waiters OR advisory-lock waiters; same bound, same assertions after it. No other existing test
needed a change in the runs below.
