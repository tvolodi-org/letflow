# GH #2551: record import keys entries without a record_id by entry index

Code: `lib/letflow/routers/entities.ex` (`import_idempotency_key/3`, called from `import_one_entry/6`). Tests: `test/letflow/routers/entities_test.exs`, describe "GH #2551 -- import entries without a record_id are keyed by entry index" (helpers `import_key_suffixes/1`, `import_entry/2`).

## Behaviour under test
Before the fix every entry with no `record_id` derived the key `entities-record-import:<request_id>:nil`, so all of them collapsed onto the first entry's record (reported "ok", one record). Now `nil` -> `...:idx:<n>` (n = zero-based position among ALL entries); a present record_id keeps `...:<inspect(record_id)>`.

Stored keys are read back from the tenant's `event_idempotency` table (stored key contains `entities-record-import:<uuid>:<suffix>`), so the tests assert the exact key shape, not only the outcome.

## Acceptance criteria -> tests
- AC1 (nil keyed by index, record_id keeps today's key): `AC1: stored keys ...` batch [nil, id, nil] -> suffixes exactly {idx:0, idx:2, inspect(id)}. Proves zero-based, counts all entries (a count over nil entries only would give idx:1), and the unchanged id key.
- AC2 (two entries, no record_id, two distinct records): `AC2: two entries with no record_id ...` two results ok, distinct record_ids, `record_count == 2`, both titles stored. Also `an explicit record_id: null ...` (null behaves as absent, three entries -> three records).
- AC3 (re-run idempotent): LIMIT, stated plainly. `import_request_id` is minted inside the HTTP handler and the key builder is private, so a same-request-id replay is not reachable without a production hook (none added). Covered indirectly: the key is request_id + a deterministic suffix, asserted exactly in AC1 and in the re-POST test, so a replay with the same id derives identical keys; `AC3 (limit)` asserts a byte-identical re-POST mints a fresh request id and writes fresh records (4 records, suffixes idx:0,idx:0,idx:1,idx:1, two distinct request ids). Intra-call dedup of the record_id kind is the pre-existing "REQ-320 intra-call" test plus the AC4 test.
- AC4 (all entries carry record_id: unchanged): `AC4: when every entry carries a record_id ...` [a, b, a(identical)] -> a deduped to one record, 2 records total, suffixes exactly {inspect(a), inspect(b)}, none starting with `idx:`.
- Extra: `mixed batch` (nil/id interleaved at 0..4: 5 distinct records, source_record_ids [nil,id1,nil,id2,nil], 5 distinct stored suffixes); `a record_id whose text looks like an index key` (string id "idx:0" vs nil entry at index 0: no collision, because inspect quotes the string).
