# ISS-1034 (GH #2355) -- separation-of-duties refusal shows a bare "Forbidden"

## Problem

The backend answers the REQ-463 distinct-person refusal on task complete
(`lib/letflow/routers/tasks.ex:395`) and assign/claim (`:493`) with HTTP 403 and the
constant body `{"detail":"separation of duties","status":403}`
(`lib/letflow/api/response.ex:61`; no title/type by design). `web/src/api/client.ts`
built `message = title ?? message ?? statusText`, so the worker saw "Forbidden", and
`TaskDetailPanel` rendered nothing at all for a failed complete/claim.

## Change (web only)

1. `client.ts` generic `!response.ok` branch: 403 + `body.detail === 'separation of duties'`
   (exact) -> ApiError `message = SEPARATION_OF_DUTIES_MESSAGE`, `code = 'SEPARATION_OF_DUTIES'`,
   `details` = body as before. Exported `isSeparationOfDuties(err)` (status 403 + that code) and
   `SEPARATION_OF_DUTIES_CLAIM_MESSAGE`. 401/429/409 branches and `classifyError` untouched
   (403 -> `permission-denied`).
2. `TaskInboxPage.tsx` `TaskDetailPanel`: `role="alert"` `data-testid="task-sod-error"` rendered
   only when `complete.error` / `claim.error` satisfies `isSeparationOfDuties`; complete uses
   the "complete this step" text, claim the "take this task" text. Cleared by react-query on
   the next mutate.

Decision (d): matching is on `detail` alone; a `title` next to the exact detail still maps.

## Tests

`web/src/api/__tests__/client.separationOfDuties.test.ts` (8 incl. each.)
- (a) exact body -> message/code/status/details
- (b) 403 `title: Forbidden` -> unchanged message and code `403`
- (c) `'separation of duties '`, `'Separation of duties'`, `'separation of duties: x'` -> not mapped
- (d) exact detail + title -> mapped
- (e) 500 with that detail -> unchanged
- guard rejects null / string / wrong code

`web/src/pages/tasks/__tests__/TaskInboxPage.sodMessage.test.tsx` (4)
- complete refused with SoD -> alert with message
- claim refused with SoD -> alert with claim message
- plain 403 Forbidden -> no SoD alert
- success -> no SoD alert
