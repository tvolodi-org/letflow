# GH-2747 test spec: keyset cursor decoders with a valid prefix and a malformed tail

Code under test: `Letflow.Api.Pagination.decode_seek_parts/3` and the ~17 keyset decoders that now
call it (`identity.ex` x3, `routers/audit.ex`, `routers/promotions.ex` platform events,
`instances.ex` x3, `dlq.ex`, `tasks.ex`, `service_catalog.ex` x2, `definitions.ex` x2,
`definitions/promotion_review_store.ex`, `entities/definitions.ex`, `repository.ex`,
`repository/activation.ex`, `repository/attachments.ex`, `repository/entity_attachments.ex`).
Before the fix each did a bare `[a, b] = String.split(...)` match plus `String.to_integer/1` and
`DateTime.from_unix!/2` on the cursor tail, so a cursor with a valid prefix and mint slot but a mangled
tail raised (`MatchError`, `ArgumentError`, `Ecto.Query.CastError`, int8 overflow) and the client got a
500. The fix returns `{:error, :invalid_cursor}`, which each router already maps to its own cursor error.

Acceptance criterion (the issue): a test per decoder with a valid prefix and a bad tail returns
`{:error, :invalid_cursor}` (context level) or the endpoint's client error (router), never a raise/500.

Tests (all real Postgres; routes go through the real `Letflow.Router` with bearer tokens, no mocks):

* `test/letflow/api/pagination_test.exs`, describe `decode_seek_parts/3 (GH 2747)` (unit).
* `test/letflow/routers/gh2747_cursor_tail_http_test.exs` (HTTP, one table-driven test per endpoint).
* `test/letflow/gh2747_cursor_tail_context_test.exs` (context, one table-driven test per function).
* helper `test/support/cursor_forgery.ex` (`Letflow.TestSupport.CursorForgery`): forges a cursor that is
  valid except for one slot, truncations, and an over-long tail, per slot-layout.

## Shared design of the table-driven tests

A cursor is `Base.url_encode64(prefix <> mint <> ":" <> slot ...)`. For each endpoint the layout is
declared (e.g. users `U:` = `[mint, dt, uuid]`, platform events `PE:` = `[mint, int, uuid]`,
definitions search `DS:` = `[mint, "rank|uuid", dt]`). For every slot and every bad value of that slot's
type there is one forged cursor, so each decoder is hit with: a missing slot, a truncated tail, an
over-long tail, non-numeric text, `-1`, a timestamp above `253402300799999999` (invalid_unix_time), int64
overflow in both directions, a non-UUID id, and for string ids an empty slot, a NUL byte and invalid UTF-8.

Every table test first asserts a POSITIVE control (the same forging with every slot valid is accepted:
200 / `{:ok, _}`), so the refusals below it are down to the one mangled slot and nothing else. The HTTP
tests assert the endpoint's own cursor-error status (400 for most, 422 for instances/tasks/attachments)
and that the body is byte-identical to the body an undecodable cursor (`!!!not-base64!!!`) already gets, with
the trace id pinned. A bad MINT slot is refused by `decode_cursor/4` before the seek decoder runs, so for
those forgeries only "a 4xx, never a 5xx" (HTTP) / "an error tuple" (context) is asserted. A far-future
mint is a valid mint (never expires, slot skipped) and is deliberately not forged for `:mint` slots.

## RED evidence

The new tests were run against the pre-fix `lib/` (`git archive 2c93b8c2 lib` in a scratchpad copy, own
`MIX_TEST_PARTITION`, repo files untouched): the HTTP file 25 failed / 6 passed (the 6 are the GUARD
round-trip and unknown-group tests), the context file 12 of 12 failed (`ArgumentError`, `invalid Unix
time`, `Ecto.Query.CastError` on `not-a-uuid`). For `decode_seek_parts/3` itself the pre-fix failure is
"the function does not exist", which proves nothing, so five mutants of the shipped helper were run:

| Mutant | Change | unit file | context file | HTTP file |
|---|---|---|---|---|
| M1 | drop the int64 bound check | 1 failed (`:int accepts the int64 bounds...`), 62/63 pass | 1 of 12 failed (`repository_list_versions`) | 4 of 31 failed (platform events table + "400 body" test, history, timeline) |
| M2 | accept a negative `:datetime_us` | 1 failed (`:datetime_us refuses a negative timestamp...`) | not run | not run |
| M3 | drop the NUL / UTF-8 check | 1 failed (`:string refuses an empty slot, a NUL byte...`) | 2 of 12 failed (both service-catalog listings) | not run |
| M4 | `String.split` without `parts:` | 1 failed (`the last slot keeps any further colons`) | not run | not run |
| M5 | `DateTime.from_unix!/2` in `:datetime_us` | 1 failed (`...refuses a timestamp DateTime.from_unix/2 rejects`) | 7 of 12 failed | 9 of 31 failed (users, group-members, audit, tenants, definitions list/search, promotion reviews, entities/definitions, audit "400 body") |

Each mutant was reverted and the revert verified before the next.

## Not tested

* The mint slot is not forged with a huge future value for `:mint` layouts: it is a valid cursor by design.
* `Entities.Query.Cursor` (`EQ:`) and `ScopedGrants` (`RG:`) were outside the issue's list and are untouched.
* Valid-cursor round trips for repository versions, activation history, attachments, dlq, tasks, audit and
  platform events are not written: each needs a costly fixture (artifact versions, uploads, failed
  instances, audit chain, promotions); their decoders share `decode_seek_parts/3` with the round-tripped ones.
