# GH #2552: API tokens record the issuer; roles a subset of minter and target; owner_inactive status

Design: `lib/letflow/design/gh2552-api-token-issuer-and-roles.md` (decision 0051 M2, D1, D8; validated in 2 rounds). Code: `lib/letflow/identity.ex` (`mint_token/4`, `tenant_wide_role_names/2`, `validate_platform_admin_expiry/4`, `token_effective_status/3`, `list_tokens/1`, shared `insert_token/5`, `token_audit_state/1`), `lib/letflow/identity/api_token.ex` (`issuer_user_id`), `lib/letflow/routers/identity.ex` (token handlers), `priv/repo/migrations/20261015000001_add_issuer_user_id_to_api_tokens.exs` plus its manifest entry in `lib/letflow/tenant_provisioning.ex`, `config/config.exs` (`:platform_admin_token_max_ttl_days`, 90).

## Behaviour under test
`POST /identity/tokens` mints through `Identity.mint_token(auth_context.user_id, user_id, attrs, opts)`. A body key `issuer_user_id` is a 422 `issuer_user_id_not_allowed` before validation and any DB access. In one transaction: `lock_tenant_admins!/1`, then the issuer and target `users` rows `ORDER BY id FOR SHARE`, then in order: (3) the issuer must exist, be active and have mint authority (`tenant_admin_mint_authority?/1`: TENANT_ADMIN group-held; OR the DEVIATION clause `platform_admin_mint_exception?/2`: PLATFORM_ADMIN group-held in the platform tenant), else 403; (4) the input checks of `create_token/3`; (5) target missing -> 404, inactive -> 422 `user_inactive`; (6) a PLATFORM_ADMIN token must target the issuer (422 `roles_invalid`) and expire within the cap (422 `platform_admin_token_expiry_invalid`); (7) roles must be a subset of both principals' `tenant_wide_role_names/2` (group-held only, never token roles), else 422 `roles_invalid`. The row stores `issuer_user_id`; `token.create`/`token.revoke` state excludes `token_hash` and `name`, adds `issuer_user_id` and `scope: "tenant_wide"`. `GET /tokens` items carry `issuer_user_id` (null for legacy) and an effective `status` with precedence revoked > expired > owner_inactive > active. `create_token/3` stays the trusted non-HTTP path with a NULL issuer.

Files: `N` = `test/letflow/routers/gh2552_token_issuer_test.exs` (new; router dispatch with a real caller, `call_as/6`), helpers in `test/support/token_mint_fixture.ex` (`role_holder!/3`, `grant_roles!/3`: roles by group membership, raw rows).

## Acceptance criteria -> tests (design section 10)

### Issuer column, server-set, legacy NULL
N, describe "issuer_user_id":
- `mint records caller as issuer_user_id`: 201; body and row carry the caller as issuer, the target as `user_id`.
- `body issuer_user_id -> 422 issuer_user_id_not_allowed, no row, no audit`: for the caller's id, the target's id, `null` and a non-UUID.
- `create_token/3 row has NULL issuer, authenticates via verify_api_token/2, lists with issuer_user_id null`.
- `information_schema: api_tokens.issuer_user_id is_nullable YES, column_default NULL` (type `uuid`).

### Roles a subset of minter AND target, 422
N, describe "roles subset (0051 M2)":
- `role not held by target -> 422 roles_invalid` (domain `{:error, :roles_not_held}` asserted too).
- `role not held by minter -> 422 roles_invalid`.
- `role held only via target's token -> 422` (token roles never count, OQ1).
- `empty roles -> 422 roles_invalid`.
- `the 422 body is fixed: identical for the target, minter and empty cases`; names no principal (INV-2).
- `non-admin caller with bad roles -> 403, not 422`: unknown role, empty roles, a role not held, an unknown target and a past expiry all give 403.

### Audit metadata
N, describe "audit":
- `token.create after_state has issuer_user_id,user_id,roles,expires_at,scope; ...`: key set pinned; actor = caller, trace = request; no `token_hash`, its 8-char prefix, `name`, `lf_tok_` or the plaintext; chain valid.
- `token.revoke before/after have the same keys; actor is the revoker; ...`: DELETE by a different admin; DELETE response has `status: "revoked"` and the issuer.
- `create_token/3 audit shows issuer_user_id nil`.
- #2547 T-30 updated: `test/letflow/routers/identity_gh2547_audit_test.exs` `@token_state_keys` now pins the GH 2552 key set; T-14a asserts the issuer.

### Effective status incl. owner_inactive
N, describe "effective status":
- `deactivated owner -> owner_inactive; revoked -> revoked; expired -> expired; revoked+inactive -> revoked; expired+inactive -> expired; active -> active` via `GET /tokens`; `list_tokens/1` `owner_active` asserted.
- `unit table for token_effective_status/3`: 10 rows, including `expires_at == now` -> expired.

### List exposes issuer, never the value
N, describe "list": `item has issuer_user_id (null for legacy), no token/token_hash`; neither plaintext nor hash in the body. Key-set pins in `test/letflow/routers/identity_test.exs` (created and list) gain `"issuer_user_id"`.

### Only a tenant-wide TENANT_ADMIN mints
N, describe "mint authority":
- `TA token but not in TA group -> 403` (HTTP and domain `:issuer_not_authorized`).
- `inactive minter -> 403`.
- `unknown or non-UUID issuer -> :issuer_not_authorized`.
- `TA mints in customer and platform tenant, no PA binding anywhere (passes unchanged with the PA clause deleted)`.
- `PA in a customer tenant cannot mint -> 403`: legacy PA binding plus membership; `tenant_wide_role_names/2` drops PA there.
- `PA in platform tenant mints own expiring PA token -> 201`.

### PA conditions (advisor)
N, describe "PLATFORM_ADMIN token conditions":
- `PA mints a PA token for another user -> 422 roles_invalid` (domain `:platform_admin_token_not_self`).
- `PA token without expires_at -> 422 platform_admin_token_expiry_invalid`.
- `PA token past the cap -> 422` (now + 90 d + 60 s).
- `PA token at the cap -> 201` (now + 90 d - 5 s).
- `the cap is read from :platform_admin_token_max_ttl_days at call time` (set to 1 day, a 2-day token refused).
- `unit: validate_platform_admin_expiry/4 at exactly the cap :ok, cap + 1 s error`; nil refused; a sub-second excess is truncated away; non-PA role sets are not capped.

### Race
N, describe "race", `concurrent remove_group_member vs mint: either 422 or the token commits before the removal`: (a) deterministic: a transaction holding `lock_tenant_admins!/1` deletes the target's membership; a concurrent mint is still waiting after 500 ms and, once the remover commits, returns `:roles_not_held`; (b) truly concurrent `remove_group_member/3` and `mint_token/4`: either `:roles_not_held` and no row, or the `token.create` entry is earlier than `group_member.removed`.

### Inactive target
N, describe "target": `inactive target -> 422 user_inactive, no row` (no `token.create`); `unknown target -> 404 for an authorized minter`.
