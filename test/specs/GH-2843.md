# GH #2843 test spec: `script_rules` cursor key validation

Defect: `Letflow.Routers.ScriptRules.decode_cursor/1` passes the cursor `key` unchecked to `Scripts.list/3`. A NUL byte or invalid UTF-8 reaches Postgres and raises (a 500) instead of the existing 422 "invalid pagination parameters".
Tests: `test/letflow/routers/script_rules_test.exs`, `describe "GH #2843: crafted cursor keys"` (6 tests). Cursors are built exactly as the router's `encode_cursor/1` does: `Letflow.Api.Pagination.encode_cursor("script-rules:" <> key <> "\n" <> version)`.

## Acceptance criteria to tests

| AC | Test | Why it exists |
|---|---|---|
| Reproducing test: NUL in key | "a NUL byte in the cursor key is 422, not a Postgres 500" | The defect itself. Asserts status 422 and detail. |
| Reproducing test: invalid UTF-8 | "invalid UTF-8 in the cursor key is 422, not a Postgres 500" (`<<255, 254>>`) | Second Postgres rejection path (0xff rather than 0x00). |
| After fix: valid cursor round-trips unchanged | "a cursor from a real first page round-trips unchanged to the second page" | Guards that validation does not reject or alter real cursors; also pins `next_cursor == crafted(k1, "1")`. |
| No behaviour change for valid cursors | "a ':' key and a non-ASCII (valid UTF-8) key are valid seek positions" | A naive check (split on ':', ASCII-only, `String.printable?`-style) would wrongly reject these. |
| No behaviour change | "an empty key is a valid seek position today" | Pins current behaviour (200, rows with key > "" returned). The fix must not start refusing it. |
| Existing 422 contract | "a version out of range or not a number is still 422" (0, -1, 2147483648, x, 1x, empty) | Regression guard that version bounding survives the fix. |

## Evidence on UNMODIFIED code (origin/main 9684a15c)

`mix test test/letflow/routers/script_rules_test.exs --only describe:"GH #2843: crafted cursor keys"`: 4 passed, 2 failed.
- NUL test: `** (Plug.Conn.WrapperError) ** (Postgrex.Error) ERROR 22021 (character_not_in_repertoire) invalid byte sequence for encoding "UTF8": 0x00` (unhandled in the router; Plug maps this to a 500).
- invalid UTF-8 test: same error with `0xff`.
- The other four are green on unmodified code, as intended (regression guards).

Note: the test asserts `conn.status == 422` and the router is called directly, so the pre-fix failure surfaces as the raised exception rather than a literal `500` status; both mean "not 422".

## Mutants for TEST-DESIGN-VALIDATOR (apply to the fixed `decode_cursor/1`)

1. Key validation removed (key passed through unchecked): NUL and invalid-UTF-8 tests must go red.
2. Validation applied to the version only (key still unchecked): same two tests red.
3. Over-strict key check that rejects a ':' (or any non-alphanumeric/non-ASCII) key: the ':'/unicode test and possibly the round-trip test must go red.
4. Key check that rejects the empty key: the empty-key test must go red.
5. Version bounds removed or loosened (e.g. allow 0 or 2147483648): the version test must go red.
