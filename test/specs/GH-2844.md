# GH-2844 -- Query.Cursor component decoding (int64 overflow, NUL / invalid UTF-8, type confusion)

Test file: `test/letflow/entities/query_cursor_components_test.exs` (real Postgres via
`Letflow.DataCase`; drives `Cursor.paginate/5` with hand-minted cursors, the same
`EQ:<mint_us>:<json>` shape `build_next_cursor/2` produces). The existing invalid-cursor
error is `{:error, :invalid_cursor}`.

## Pre-fix result (unmodified main 9182b04e)

`Result: 40/52 passed`, `Failed: 12 tests`. The 12 RED tests raise instead of returning
the error:

| Test | Real failure on main |
|---|---|
| int64 max + 1 | `DBConnection.EncodeError: Postgrex expected an integer in -9223372036854775808..9223372036854775807, got 9223372036854775808` |
| int64 min - 1 | same, `got -9223372036854775809` |

| string for `:boolean` field | `DBConnection.EncodeError: Postgrex expected a boolean, got "maybe"` |

| boolean for `:decimal` field | `FunctionClauseError in Postgrex.DefaultTypes ...Extensions.Numeric` |

The last four are the same defect class via the same catch-all clause
(`decode_component(_type, v) when is_binary(v) or is_boolean(v)`), found while probing;
they are in scope of "check the other clauses" and should be fixed with the same change.

## Cases that do NOT fail on main (recorded, as the issue allows)

- Invalid UTF-8 bytes (`<<255,254>>`) in a string sort component or in the id component,
  and a lone-surrogate escape (`\ud800`): already `{:error, :invalid_cursor}` because
  `Jason.decode/1` rejects them before `decode_component/2` is reached. Kept as guards.
- NUL byte in the id (tie-break) component: rejected by the UUID cast
  (`Pagination.cast_binary_id_component/1`); the id does not take the catch-all clause.
- `:decimal` (strict and legacy fields): malformed text, `NaN`, `Infinity`, `1e99999`, `""`
  already error (GH #2654). `:date` / `:datetime` malformed or wrong-typed components error.
  Extreme-but-parseable date/datetime (year 0000, 9999, offset) do not raise (probe tests;
  they accept either `{:ok, _}` or the error, since the choice is not part of this issue).
