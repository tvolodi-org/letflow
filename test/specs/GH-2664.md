# Test spec: GH #2664 / REQ-507 (catalog_items behaviour, read API, isolation, limits runbook)

All tests are integration tests on real Postgres with real provisioned tenants and the real
installed `catalog_items` module (no mocks). Shared fixture:
`test/letflow/modules/catalog_items/catalog_items_fixture.exs` (`Letflow.CatalogItemsFixture`),
a `.exs` loaded with `Code.require_file("catalog_items_fixture.exs", __DIR__)`, deliberately NOT
a `test/support/**/*.ex` file: `owner_for!(Letflow.Modules.CatalogItems)` outside
`lib/letflow/modules/catalog_items` is rejected by the R1/R2 guard in
`test/letflow/entities/managed_types_callers_test.exs`, which scans `test/support/**/*.ex`.
Owner path: `Records.create_record/update_record/delete_record` `/3` with
`ManagedTypes.owner_for!(Letflow.Modules.CatalogItems)`.

Files: `behaviour_test.exs` (AC1, AC3), `read_api_test.exs` (AC2, AC4, isolation),
`runbook_test.exs` (AC5). The existing `install_test.exs` already has X-01..X-06 for
uniqueness and kind; the files here add the per-type idempotency, key-reuse branch and
path-asserting checks and do not replace those.

## Acceptance criteria to tests

| AC | Test | Why it exists |
|---|---|---|
| AC1 duplicate code | behaviour `U-catalog_uom`, `U-catalog_item` | Second record with the same `code` (different name): `{:error, {:record_payload_invalid, [%Violation{rule: :unique, path: ["code"]}]}}`; a different code is accepted so the refusal is about the code. |
| AC1 idempotency | behaviour `D-01-catalog_uom`, `D-01-catalog_item` | Same actor + key + payload twice: `is_duplicate` true, same `record_id` and `last_event_global_seq`, one record. |
| AC1 key reuse | behaviour `D-02`, `D-03`, `D-04` | D-03: same actor + same key + different payload (isolates the payload comparison in `same_request?`). D-04: same key + same payload + different actor (isolates the actor comparison in `match_original/3`). D-02: different payload and actor; the refused payload is not stored. |
| AC1 external_ref NULL | behaviour `E-<type>-null` x2 | Two rows with both external_ref fields absent are accepted (NULLs are distinct in the unique index). |
| AC1 external_ref pair | behaviour `E-<type>-pair` x2 | Duplicate non-NULL pair is `%Violation{rule: :unique, path: ["external_ref_system", "external_ref_id"]}` (different code, so only the pair collides); same id in another system and another id in the same system are accepted. |
| AC3 kind | behaviour `K-01`, `K-02` | `kind` missing and `kind` "other" are each `{:error, {:record_payload_invalid, [...]}}`. The element is a `Letflow.EventStore.Registry.ValidationFailure` (the event-type payload schema rejects it before the DB), so the path assertion is `field_path: "/kind"` with `constraint: "required"` / `"enum"` and `actual: "other"` (JSON-pointer form, not a `Violation` path list). |
| AC3 (extra) | behaviour `K-03`, `K-04` | material and service accepted; a refused kind stores nothing (code stays free). |
| AC2 lookup/active? | read_api `R-<type>` x2 | `record_id`, `entity_type` and every stored field are in the map; `active?` true. |
| AC2 | read_api `R-<type>-inactive`, `-deleted`, `-uppercase` x2 | Inactive: found, not active. Soft-deleted: `:not_found` / false. Uppercase uuid is cast to canonical and found. |
| AC2 | read_api `R-unknown`, `R-nonuuid`, `R-rawbinary`, `R-nonbinary-prefix` | Unknown uuid, nil/123/"x"/""/map/list/atom/float/invalid UTF-8 never raise. A raw 16-byte binary of a real uuid IS found (current behaviour of `Ecto.UUID.cast/1`, documented, not endorsed); 15/17-byte binaries and an unknown 16-byte binary are not found. Non-binary prefix is not found / false for all three functions. |
| Hostile input | read_api `H-01` | NUL prefix/suffix, trailing invalid UTF-8, 100k string, 36 zeros, leading space: never raise for `lookup`, `active?`, `item_uom_valid?` (either argument). |
| Documented limit | read_api `H-02` | A well-formed but unprovisioned `tenant_<32 hex>` prefix raises `Postgrex.Error` (undefined_table), as the moduledoc and runbook limit 8 say. Deterministic and cheap. |
| AC4 item_uom_valid? | read_api `V-01`..`V-11` | V-01 true; V-02 inactive item; V-03 inactive unit; V-04 unknown item, unknown unit; V-05 `base_uom_id` naming a unit that does not exist (no reference check on write, false on read); V-06 non-uuid for either argument; V-07 a different ACTIVE unit is false (base unit only); V-08 unit id used as item and vice versa; V-09 soft-deleted unit and soft-deleted item; V-10 uppercase uuids for the real base unit and item are true (cast, as implemented); V-11 stored uppercase `base_uom_id` fails closed (runbook limit 7). |
| AC2 isolation | read_api `T-01`, `T-02` | Two tenants. B's prefix never returns A's records for `lookup`, `active?`, `item_uom_valid?`; the same code in B is independent. T-02: a B item whose `base_uom_id` is A's unit id is `item_uom_valid?` false in B (the unit is not in B), with a control true in A. |
| AC5 runbook | runbook `B-01`..`B-07` | Exact heading "## Catalog module limits"; numbered list 1..N (>= 8) with the known limits; each limit cites a GH number or a path; GH refs plain numbers; every cited path exists and cited lines are in range; cited lines still hold the symbol (stale-line detector); catalog module and item definition paths are cited. Scoped to the Catalog section only; the Org section has its own test. No network. |

AC6 (SECURITY/REVIEWER verdicts, compile, format, boundaries) is not test-designer scope.

## Mutants for TEST-DESIGN-VALIDATOR (NOT applied by the designer for TDV; designer-verified below)

Apply one at a time to `lib/letflow/modules/catalog_items/catalog_items.ex`, run the three test
files, revert. Counts are the designer's own measurement (baseline: `Result: 78 passed` for the
three new files plus `managed_types_callers_test.exs`; read_api alone 27 tests, behaviour 15,
runbook 7). Each was applied from a scratchpad copy and restored by file copy plus `cmp`.
