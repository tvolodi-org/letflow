# GH #2589: the web tokens page types and displays the four #2552 statuses and the issuer

Issue record: GH #2589 (web, display only; depends on #2552). Contract: `lib/letflow/routers/identity.ex` `token_map/2` and `lib/letflow/design/gh2552-api-token-issuer-and-roles.md` (§ "List", and the note at :202-203 that filed this issue). The page is `web/src/pages/admin/TokensPage.tsx`; the type is `web/src/types/api.ts` (`ApiToken`).

## Defect
After #2552, `GET /identity/tokens` items carry `status` in lowercase, one of `active | revoked | expired | owner_inactive` (precedence revoked > expired > owner_inactive > active), and `issuer_user_id` (null for legacy rows). The web client did not match:
- `ApiToken.status` was typed `'ACTIVE' | 'REVOKED' | 'EXPIRED'` (uppercase, no `owner_inactive`), duplicated as a local union in `TokensPage.tsx`; `ApiToken` had no `issuer_user_id`.
- The Status cell picked its colour from `revoked_at` only. Every row without `revoked_at`, including `expired` and `owner_inactive`, was drawn in `--color-success-dark` (the active green). It printed the raw `status` string and fell back to `'ACTIVE'` when the status was missing.
- The issuer was not shown.

An expired token, or a token whose owner is deactivated, looked active to an admin.

## Acceptance criteria (from GH #2589)
1. `ApiToken.status` is `'active' | 'revoked' | 'expired' | 'owner_inactive'`; the local duplicate is removed; `ApiToken` gains `issuer_user_id`.
2. Each status has a distinct label and style; only `active` uses the success colour; a missing or unknown status renders a neutral "Unknown", never "ACTIVE".
3. The issuer is shown, resolved to a display name from user data the page already has, falling back to the id; a legacy token shows a dash.
4. A component test asserts the labels, that only the active row is green, and the issuer display, and fails on main.
5. The test does not mock `web/src/api/*` or the query hooks; it serves the list at the network boundary.
6. No backend change.

## Decision
- `ApiTokenStatus` is exported from `web/src/types/api.ts`; `ApiToken.status?: ApiTokenStatus`, `ApiToken.issuer_user_id?: string | null`. The `status` line of the local `TokenRow` type is removed (it inherits `ApiToken`'s).
- `TOKEN_STATUS_PRESENTATION: Record<ApiTokenStatus, {label, color}>` (exhaustive by type): `active` "Active" `--color-success-dark`; `revoked` "Revoked" `--text-disabled`; `expired` "Expired" `--color-warning-text`; `owner_inactive` "Owner inactive" `--color-error-dark`. Any other wire value, or none, is "Unknown" in `--text-secondary` (an own-property lookup, so a value such as `toString` cannot hit the prototype). Existing tokens only, no new CSS.
- New column "Issued by" (`id: 'issuer'`), placed after Created so the existing e2e `td` index (`nth(3)`, Created) is unchanged: `usersById.get(issuer_user_id)?.display_name`, else the id, else "—" for null/absent. `usersById` is the page's existing `GET /identity/users?page_size=200` result.
- The status span carries `data-testid="token-status"`. The e2e spec `web/tests/e2e/f5-admin-groups-tokens.e2e.spec.ts` pinned the old uppercase text (`toContainText('ACTIVE')` / `'REVOKED'`, case-sensitive), which #2552's lowercase wire value had already broken; its three assertions now read `token-status` and expect "Active" / "Revoked". `sim-admin-processes.pipeline.e2e.spec.ts` uses Playwright's case-insensitive `getByText('ACTIVE')` / `getByText('REVOKED')` and still matches; it is unchanged.
- The Revoke button and the revoked-row strikethrough still key on `revoked_at` (unchanged; an expired or owner-inactive token can still be revoked).

## Test cases (`web/src/pages/admin/__tests__/TokensPage.gh2589.test.tsx`)
Harness: the real `TokensPage`, `@/api/identity`, `@/api/client` and a real `QueryClientProvider` (retry off) inside a `MemoryRouter`. Only `window.fetch` is stubbed with `vi.stubGlobal`, as a URL router: `GET /api/v1/identity/tokens` returns five items in `token_map/2`'s wire shape, `GET /api/v1/identity/users` returns two users, anything else is a 404. `@/auth/AuthContext`'s `useAuth` is replaced (spreading the real module) because `useTenantScopedQueryKeys` needs a session. This is the harness of `web/src/pages/tasks/__tests__/TaskInboxPage.sodMessage.test.tsx`. MSW is forbidden by the guard suite (`web/tests/guards/forbidlist.ts`, `msw-import`).

Fixture rows, in render order: `active` (issuer `u-issuer`, a known user "Issuer Admin"); `revoked` with `revoked_at` (issuer `u-gone-issuer`, not in the user list); `expired` (issuer `null`); `owner_inactive` (no `issuer_user_id` key); and a row with no `status`.

- `only the active row uses the success (green) colour; revoked, expired, owner_inactive and a missing status do not`: the status span's `style.color` is `var(--color-success-dark)` on the active row, and contains no `success` on the four others.
- `each status has its own human-readable label, and a missing status reads "Unknown", never "ACTIVE"`: exact text "Active", "Revoked", "Expired", "Owner inactive", "Unknown"; the four known statuses have four distinct colours.
- `shows the issuer: a known user by display name, an unknown id as the id, a null or absent issuer (legacy) as a dash`: the `issuer` header exists; cells read "Issuer Admin", "u-gone-issuer", "—", "—".

The status element is located as the first `span` in `datatable-cell-status`, which exists on main too, so the first two cases fail on main by assertion, not by a missing test id.

## Fail-first evidence (by inspection, and the hosted gate)
Commit 1 adds only the test. On main's page:
- Case 1 fails: the expired, owner_inactive and no-status rows have no `revoked_at`, so main's `revoked ? 'var(--text-disabled)' : 'var(--color-success-dark)'` draws them green; `style.color` is `var(--color-success-dark)`, which contains `success`.
- Case 2 fails: main prints the raw wire status (`active`, not `Active`) and `'ACTIVE'` for the missing status.
- Case 3 fails: main has no `issuer` column (`datatable-header-issuer` is absent).

Commit 2 adds the fix and this spec. All three cases pass on it by the decision above.

Local run: skipped. The host had about 0.6 GB of free memory, so `npm run type-check`, `lint`, `test` and `guards` were not run locally. The evidence is the hosted CI job "Frontend gate (npm run check)" on the PR: red on the test-only commit, green on the fix commit. TypeScript and lint were checked by reading against `web/tsconfig.app.json` (strict, `noUnusedLocals`, lib ES2022 for `Object.hasOwn`) and `web/.eslintrc.json`; the test file was checked against the guard patterns (no `fetch(` call text, no colour literal outside comments, no inline query key).
