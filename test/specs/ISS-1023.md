# ISS-1023 test spec: `entries` of the /context `serialised_plan` only for plans whose both sides are the caller's own tenant

Design: `lib/letflow/design/iss1023-context-entries-own-sides.md` (Q-1005 / GH #2297). Regression test:
`test/letflow/routers/promotion_context_entries_scope_test.exs` (T-13). Updated: T-8 `promotion_context_shaping_test.exs`,
T-11 `promotion_context_allowlist_test.exs`, T-12 `promotion_context_allowlist_drift_test.exs`.

Rule under test (non-operator only): `entries` as stored iff it is a list AND `source_tenant_id` and `target_tenant_id` both
satisfy `own_tenant_value?/2` (own id, case-insensitive); `[]` otherwise (foreign, missing, null, non-binary, empty, padded).
Operator view unchanged.

Fixture note: the plan digest covers `entries` only and is unique per schema while a review is pending, so T-13 gives each
seeded review distinct entries through a non-marker `seq` field.

## Note on ISS-1021 residual R1 (superseded by ISS-1023)

`test/specs/ISS-1021.md` R1 ("`entries` graph JSON is copied as stored ... for an operator-created review naming foreign tenants")
is CLOSED for plans naming a foreign tenant: a non-operator no longer receives another tenant's graph content through `entries`
(`[]` instead). The ISS-1021 spec is historical and not edited. The answer to its open question: today only `PLATFORM_ADMIN` holds
`:PromotionsRead`; non-admin platform-tenant users do not (T-13 AC5 test).

REQ-447 ordering note: this fix should land before `TENANT_ADMIN` / `TENANT_AUDITOR` receive `:PromotionsRead`; the AC5 test is the tripwire.

* R3: `teardown_error` text on other review routes.

* R9: `entries == []` lets a non-operator infer the review names another tenant.
* R10: approve/reject do not gate on the stored tenant ids. TRACKED as Q-1008 / GH #2305 / ISS-1026.

## Note (ISS-1029, Q-1011)

The entries gate (all-or-nothing on both stored ids) is now defence in depth for a non-operator: a review whose stored ids are
not both the reader's own is answered with the nonexistent-review 404 before `shape_plan/2` runs, so `entries == []` for a
foreign-named review is no longer observable through the route. R9 ("`entries == []` lets a non-operator infer the review names
another tenant") is CLOSED by the same change. See `test/specs/ISS-1029.md`.
