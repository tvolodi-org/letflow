# Test Spec: GH #2759 -- a soft-deleted question must not start via a manual pin and is not drawn from a pool

**Issue:** GH #2759. Binding design (RULED): `lib/letflow/design/gh2762-exam-soft-deleted-reads.md`, section 3.2 and
test rows T-59a..T-59e. Implementation: `fetch_pinned_question_row/2` uses `Latest.get_live/3`;
`fetch_pool_questions/2` adds `eq("deleted", false)` (`lib/letflow/modules/exam/session.ex`, commit 8a3f8d28).

**Test tier:** integration against real Postgres and real provisioned tenants (DIRECTIVE T-1); no mocks.

**Files:** `test/letflow/modules/exam/session_test.exs` (describes "GH #2759 -- manual pin to a soft-deleted question",
"GH #2759 -- a soft-deleted question is not drawn from a random pool"), `test/letflow/modules/exam/exam_sessions_test.exs`
(describe "GH #2759 -- HTTP start with a pin to a soft-deleted question").

Legend: RED = fails on main (main reads pins with `Latest.get/3`, which returns a soft-deleted row, and the pool query
has no `deleted` predicate); derived from `git diff 7e8f75ad..HEAD -- lib`, not from running main. GUARD = passes on
main and pins behaviour that must not regress.

| ID | Test | Why it exists | On main |
|---|---|---|---|
| T-59a | Manual pin to a question deleted via `Records.delete_record/2` while `status = active` -> `{:error, {:question_not_found, id}}`; no `session`/`session_question` rows | Core bug; nothing may be written on refusal | RED (start succeeds) |
| T-59c | Deleted-pin result equals `{:error, {:question_not_found, <pinned id>}}`, the same shape as a pin to a nonexistent question | Refusal must be indistinguishable from "no such question" | RED |
| T-59b | HTTP `POST /exam-sessions`, deleted pin vs nonexistent pin: both 422, `resp_body` byte-identical (trace id pinned), body does not contain the deleted id | Router renders the constant body; no leak | RED (main answers 201) |
| T-59d | Random rule with `count` == pool size (3) and one deleted active question: start returns the resolver's `{:error, :pool_underflow}` (read from `QuestionSetResolver.pick_from_rules/2`: fewer candidates than `count`), nothing written | Deterministic: on main all 3 incl. the deleted one are always drawn; now the pool is 2 < 3 | RED |
| T-59g | Pool of 4 (one deleted), `count` 3: the drawn ids are exactly the 3 live ones | Live pool questions are still drawn and the deleted one never is | GUARD in intent (passes after the fix always; on main it passes only if the random draw happens to skip the deleted one, 1 in 4) |
| T-59e | Two exams: one with a deleted pin (refused), one with live pins (starts, pinned order kept) | Over-filtering guard: only the deleted question is excluded | GUARD |
| T-59e2 | HTTP start with a pin to a live question -> 201 | HTTP-level guard | GUARD |
| T-59f | Pin that is not a UUID -> `{:question_not_found, "not-a-uuid"}` | Unchanged malformed-id branch | GUARD |

## Mutants (design section 7), for the validator to apply

* Revert `fetch_pinned_question_row/2` to `Latest.get/3`: T-59a, T-59c, T-59b must fail.
* Remove `eq("deleted", false)` from `fetch_pool_questions/2`: T-59d must fail (deterministically), T-59g probabilistically.
* Invert/over-filter the pool predicate (`deleted` true): T-59g and T-59d's sibling guards must fail.
