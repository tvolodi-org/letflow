## Hard facts that shape the tests (found by running, not assumed)

| Fact | Effect |
|---|---|
| `tasks.scope_node_id` has no production writer; a task made by the engine has a NULL node | `start_task!/3` creates through the real engine and `set_scope_node!/3` then places it |
| Test names (with the `describe` prefix) must stay below the atom limit (about 240 characters) or the file does not compile | names are short; a check script gates it |
| Only `assign_task/3` writes a `task.assign` audit entry; claim and reassign write none | the audit test checks EVERY task entry, so a future writer is covered |
| `Tasks.claim_task/3` / `Engine.complete_task/3` answer `task_not_pending` for a non-pending task BEFORE the recheck | pinned at the context layer; at HTTP the router-level `in_scope/3` runs first, so completed and cancelled out-of-scope tasks give the same 404 |
| The requests are hand-built `auth_context` dispatches into the router (no `AuthPipeline`), so no API token row is touched | the second-boundary flake of #2729 (`last_used_at` truncated to the second across token-user requests) cannot occur; no statement count crosses a token request |
| `with_log` also captures Ecto debug QUERY lines | the only log assertion counts OUR constant line (`scope_set_failed`) and refutes nothing about ids |
| `LOG_LEVEL=error` hides the warning `tasks_distinct_from_test` A-15 asserts on | that existing file is run at the default level (13 passed); it is not an F1 regression |
| The scan test reads `lib/` from disk | in-memory mutants of source cannot be seen by it; its liveness is proven by the seeded writer forms instead |
