Code under test: `lib/letflow/idempotency/squat_audit.ex`, `lib/letflow/idempotency/squat_remediation.ex`, `lib/letflow/release/idempotency_squats.ex`, `lib/mix/tasks/letflow.audit_idempotency_squats.ex`, `lib/mix/tasks/letflow.remediate_idempotency_squat.ex`, runbook `docs/runbooks/idempotency-key-squat-audit.md`.

## Why each test exists (not a restatement of the criterion)

A1 (read-only audit, per tenant, certificate): a wrong flag is worse than a missed one because remediation acts only on flags, so every rule R1-R4 has a test that fails if that single rule is deleted, and the clear/legitimate shape has a test that fails if a rule is over-broad.

- **T1/T2 (A):** `R3 actor mismatch` asserts the full finding shape (stored/expected actor, target, event type and timestamp, tenant, schema, squat entity/record). `R1`, `R2`, `R4` each use a row that satisfies the other three rules, so only the rule under test can flag it. The legitimate shape is absent. `rule order` pins that the event-type rule wins. `session_not_found`, `target_not_uuid`, `event_missing` are report-only (they must never become flags). `events_archive` row is classified (a join that forgot the archive would report `event_missing`). `$ref` payload: R1/R3 still apply, otherwise `payload_unresolved`.
- **T3 (A):** one generated test per family in the design table, each with a squat (flagged, with the right reason) and the verified legitimate shape (absent). Actor-rule families: `script_run:`, `effect_applied:`, `ordering_lag_exceeded:`, `promotion_assertion_teardown_failed:`. Timer families (`timer_fired:`, `escalation_timer_fired:`): actor rule and client-type rule, plus the derived `::sub_process_` actor-only rule (where `INSTANCE_STARTED` is legitimate). Type-only families: `attachment_*`, `definition_*`, and the client-types group `service_task_dispatch:`, `service_task:`, `script_task_dispatch:`. Report-only: `entities-record-import:`, `req345-seed-`, `sys:`, derived keys of other bases. A completeness test pins that the covered families equal `SquatAudit.families()`, so a prefix added to `Idempotency` later fails here until given a rule. `serviceXtask:` (the `_` wildcard case) and caller-namespaced keys are not scanned. 520 extra rows prove the keyset batching (500) loses nothing. Findings order is inserted_at then key.
- **T6 (A), read-only:** (a) AST source scan of `squat_audit.ex` (docs and comments excluded, so a moduledoc cannot trip it): no `Repo.insert|update|delete|*_all`, no `repo.<write>` on a variable, no `Multi`, no `Audit.`, no write keyword in a `fragment`, and `Repo.query/query!` only with the two constant `SET LOCAL` module attributes (their values are asserted). The same scan is run on a synthetic module to prove it bites. The wrapper and the two Mix tasks must contain no Repo call at all. (b) **Probe seam** (no production hook): the test renames `entity_record_latest` and puts a view of the same name over it whose filter calls a plpgsql function that INSERTs into a probe table. The certificate rule reads that view, so a write is attempted inside the audit's own transaction: it must come back `{:error, {:query_failed, %Postgrex.Error{code: :read_only_sql_transaction}}}` (SQLSTATE 25006) with an empty probe table. The same probe through `classify_key/3` (outside the audit) succeeds, and through `SquatRemediation` removes the key, which proves classification runs read-write there. (c) Row counts of `events`, `event_idempotency`, `audit_entries` are identical after `audit_tenant` and `audit_all`. A write right after an audit works (no read-only setting left). A held `ACCESS EXCLUSIVE` lock gives `{:error, :lock_conflict}` (2s lock_timeout); `audit_all/0` keeps going when one tenant's schema is gone.
- **Tenant isolation (A, R):** another tenant's row is never listed, never removed, never gets an audit entry; the same key in tenant B is untouched by a remediation addressed to A, and a B-only key is `:already_clear` when addressed to A. Unregistered/malformed tenant ids are `:unknown_tenant`.

A3 (explicit remediation, exact key, refuses unflagged, audited, idempotent):

- **T4 (R):** audit, remediate, re-audit, then the real `Certificate.issue_or_get_for_user/3` in ONE test with a real exam, two real submitted sessions: before the fix the squatted candidate is refused; after `:removed` the re-audit is `[]` and the candidate gets `first_issuance: true`; the legitimately issued other certificate was never flagged; the squat's event row is left (D2) so the key text has two events; one audit entry with action, resource (`resource_id` is the removed row's id, never the key), nil actor, `finding_ref` `GH #2597`, `rows_removed` 1, operator, stored/expected actor, reason, squat entity type and record id, a chain hash, and `Audit.verify_chain/1` is `:valid`. Concurrent issuer: a transaction holds the DELETE of the squat row uncommitted (the state of a remediation between DELETE and COMMIT); the issuer started meanwhile does not complete (500 ms yield returns nil), and completes with `first_issuance: true` once the delete commits.
- **T5 (R):** a clear row and a clear certificate row are refused `{:not_flagged, ...}` with counts unchanged and no audit row; report-only rows (`entities-record-import:`, `req345-seed-`, `sys:`, derived, non-family) are refused with their reason; a nonexistent key is `:already_clear` with no audit entry; invalid key (empty, 256 bytes, NUL, invalid UTF-8, non-binary) and a 255-byte boundary; invalid operator (empty, blank, 101 bytes, NUL, invalid UTF-8, non-binary) writes nothing, 100 bytes is accepted; matching is exact (`%`, `_`, trailing space, case, prefix-only keys match nothing, a literal `%` key is removed only by itself); a row lock held past the 2s lock_timeout gives `:lock_conflict` with nothing written, and the same call succeeds once the lock is released.
- **T6 (R):** second and third call are `:already_clear`, audit count stays 1; after the legitimate writer re-claims the key a repeat is `:not_flagged` and deletes nothing; the audit entry has exactly the documented `before_state` keys, no `payload`/`field_values` key and none of the payload's content (a unique marker in `field_values` is absent) and the key text appears nowhere in the entry (`resource_id`, `before_state`, `after_state`); only the one idempotency row is removed (events untouched).

A4 (operator surface, runbook):

- **T7 (W):** wrappers are called in-process, so a `System.halt` would kill the VM: `audit/0` prints `FLAG`/`FINDING` lines, a `TENANT` count line and a `SUMMARY` line and returns the summary; writes nothing; never prints payload/`field_values` content; a key with newline/ESC/control bytes cannot forge a line; a tenant whose schema is gone is in `errored`, printed with the SQLSTATE atom only (no Postgrex message), and the others still run. `remediate/3` prints the resolved `TARGET tenant schema key` before acting, then `OK`; refusals print `ERROR ...` and return `{:error, _}`; `:lock_conflict` is a returned value, not a raise. `audit_exit_code/1` (0 iff no errored tenant) and `remediate_exit_code/1` (0 for any `{:ok, _}` incl. `already_clear`, 1 for any `{:error, _}`) are tested directly and from real results. AST check: the wrapper module contains no `System.halt/stop` and no `:erlang.halt`; both Mix tasks halt only via `System.halt(code)` of the exit-code helper; the remediate task raises `Mix.Error` (usage) on wrong arity. The runbook exists and names both wrapper calls, both Mix tasks and `rpc`.
