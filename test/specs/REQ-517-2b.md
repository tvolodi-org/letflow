## T-G1: how the fixture was derived (stated, not hidden)

`test/fixtures/route_scope/off_shadow_responses.json` was NOT captured from a running `main`. The brief allows
reasoning from main's code when a `git worktree` of `origin/main` cannot be built; this machine is memory
constrained and the mix mutex was held, so each of the twelve responses was DERIVED by reading main's code
path: `Letflow.Api.Error`/`Response` serialisation (problem JSON key set `type/title/status/detail/trace_id`,
compile-time base `https://bpm.example.com/problems/`), the `Instances`, `Tasks` and `Identity` handlers
(empty page `{"items":[],"next_cursor":null,"count":0}`; `not_found`; `instance_id is not a valid UUID`; the
`status must be one of PENDING, COMPLETED, CANCELLED` 400), the `Authorize` coarse deny (`insufficient
permissions`), the `authz_unmatched(:ordinary)` 403, and `AttachmentLinks.verify` (the fixed 410 text, which
`req386_attachment_links_routes_test.exs` also pins). The 2b diff to the lib files touching these paths was
read and changes none of them for `off`/`shadow`. The fixture's `_provenance` field says the same.

Consequences: the test compares DECODED JSON plus the content type to the fixture (not raw bytes, because key
order and the `type` base are config-dependent) and ADDITIONALLY compares the raw body and ALL response headers of
`off` against `shadow` (byte identity proper). It also asserts the shadow observer really ran (would-deny
events under `shadow`, none under `off`) and has a negative control under `on`. If the replay fails on
BOTH off and shadow in the same way, the derivation is wrong and the file must be regenerated from `main`
(stash `lib priv`, run the twelve requests, write the file); if it fails on `shadow` only, 2b changed an
HTTP response.
