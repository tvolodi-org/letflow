## T-S4: how the recorded rows were obtained (stated, not hidden)

`test/fixtures/route_scope/off_shadow_responses_2c_i_b.json` has fourteen rows for the six reclassified routes (M1 x2, M2 x2, H1 x3, E8 x2, E9 x2, E10 x3). They were NOT captured from a running `main` (the machine shares one mix mutex across several sessions; the 517 fixture `off_shadow_responses.json` has the same provenance and says so). Each row was DERIVED by reading the handler code of `main` (`git show HEAD:lib/letflow/routers/{me,help,entities}.ex`, commit `ed822c606`): which branch of the handler a request takes and what `Response`/`Error` serialise for it. The rows deliberately use shapes whose answer does not depend on tenant data (empty modules list, home-tenant-only memberships, unknown screen, unknown entity type, missing screen id, a body type that differs from the path), so the derivation is mechanical. The fixture's `_provenance` carries the same statement and the argument that a replay against the working tree equals a replay against main: `git diff HEAD lib/letflow/routers` shows these handlers changed only by the `scope:` option and, in the three entity handlers, by one `ScopeGate` call that returns `:all` with no query unless the tenant is `on`. The replay also runs every row under `on`, where the same answers must hold (the shapes are decided before any scoped data is read), which catches a gate or backstop that turns a 200 envelope or a 4xx into a 500. If a row ever fails under BOTH off and shadow the derivation is wrong (re-read the handler); if it fails under only one, or only in the working tree, behavior changed.

## Findings (not implementation bugs of this slice; routed, not fixed here)

1. PRE-EXISTING: `POST /entities/query` and `.../export` with a join clause carrying `"type": "left"` raise `ArgumentError: invalid join qualifier "left"` from `Compiler.add_hop_join/4` (the wire string is never converted to the `:left` atom; `parse_join_clause/1` passes it through). It is not reachable from this slice's changes and is not scope related. The wire cannot express a LEFT join today, so the "left join keeps the primary row" half of design T-C7 is proven at the compiler (2c-i-a) and not over HTTP.
2. SEC step-12 F-2 is still true (a `@self_service_routes` entry for an unmounted route, or an entry whose key differs from the route's, is not reported by the walk). The new tests pin it as documented current behavior in one test (`a list entry for a route that is not mounted does not fail the walk by itself`) and add a test-level check that every shipped entry IS mounted with the same class, key and `:declared` source (the real-table test), so a drift of the shipped list fails there.
3. Design 4.2 says a `:pending_sec_ruling` entry is "printed by the walk in a stable line the PR body copies". The code has no such printing (the marker is only validated). T-S8 therefore pins the list (none pending) and the marker rules, not a printed line.
