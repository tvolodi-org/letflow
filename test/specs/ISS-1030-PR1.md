### Concurrency test

"two concurrent bind_tenant_realm calls with different realms ...": a Task holds
`SELECT ... FOR UPDATE` on the tenant row in an open transaction; two binders are started; the test
polls `pg_stat_activity` (bounded attempts, a repo round trip per poll, no sleep) until BOTH wait on a
lock behind a `FOR UPDATE` read of `tenants`; only then the holder is released. Expected: exactly one
`{:ok, _}`, one `{:error, :realm_already_bound}`, one entry per chain.

## Items that may FAIL for a real reason (lib findings, not test errors)

1. `Regex ~r/^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$/` is used unanchored-at-end in
   `Letflow.Oidc.RealmProbe.Httpc` and `Letflow.Identity.Tenant.realm_id_format?/1`: PCRE `$` also
   matches before a final `"\n"`, so `"realm\n"` is accepted. The router trims first, so the HTTP path
   is not affected, but the probe's own "refuse a name outside the alphabet" and the context's
   `bind_tenant_realm/3` accept it. Pinned by two separately-named tests
   ("refuses a realm name with a trailing newline ..." and "realm_bind_changeset rejects a value with a
   trailing newline ..."); the fix is `\z` (or `D`) in both regexes.
