### Realm probe file

14 design names (one renamed to the test's wording: "maps a 404 to not_found and a closed or refused
connection to unreachable"; the timeout case is in "no stray http message after cancel or timeout") plus:
delegation through the configured adapter; foreign request ids (messages with another ref injected into the
probe's Task from the server's responder, which finds the Task through `$callers`) are ignored; upper-case
`HTTPS` normalised and still verified (match and mismatch); upper-case `HTTP`; a doubled slash of an
unstripped base URL is not accepted; unknown scheme / no scheme / unset base URL -> unreachable with no
request (the live server's own port is used, so an ignored scheme would reach it); the exact-64-KiB boundary
(accepted) and one byte over (refused); a trailing newline in the realm. The TLS tests use
`:public_key.pkix_test_data/1` with explicit prime256v1 keys (the same fixture rule as `smtp_sink.ex`), and
`:public_key.cacerts_load/1` with a positive control (a certificate for the right host from the SAME trusted
CA is accepted), so the negative result is the host name check and not an untrusted CA. The CA store is
snapshotted and restored after each test (it is VM-global). Exactly one test waits for the 3 s probe deadline.

### Concurrency test

"two concurrent bind_tenant_realm calls with different realms ...": a Task holds
`SELECT ... FOR UPDATE` on the tenant row in an open transaction; two binders are started; the test
polls `pg_stat_activity` (bounded attempts, a repo round trip per poll, no sleep) until BOTH wait on a
lock behind a `FOR UPDATE` read of `tenants`; only then the holder is released. Expected: exactly one
`{:ok, _}`, one `{:error, :realm_already_bound}`, one entry per chain.

## Lib findings (fixed in this PR)

1. The realm format regex used `$`, which PCRE also matches before a final newline, so `"realm\n"` was
   accepted by the probe guard and by `bind_tenant_realm/3`. Fixed: `\z` in `Letflow.Oidc.RealmProbe` and
   `Letflow.Identity.Tenant`. Pinned by "refuses a realm name with a trailing newline ..." and
   "realm_bind_changeset rejects a value with a trailing newline ...". The design text is amended to `\z`.
2. A same-realm re-bind on a non-active tenant returned 200 (the same-realm branch ran before the status
   check). Fixed: the status check runs first, so the answer is 409 `tenant is not active` (design 3.2).
   Pinned by the bind-level test "a non-active tenant answers tenant_not_active even when the same realm is
   already stored (design 3.2)" and the router-level test of the same name pattern.
3. SECURITY-REVIEWER F1 (BLOCKER): the create path wrote the realm with the tenant, before provisioning and
   the onboarding record. A taken hostname then left an active tenant owning the realm, and nothing in the
   API could undo it. Fixed: the create path refuses a realm already bound (409, no write), creates the
   tenant without the realm, and binds it only after provisioning and the onboarding record succeed,
   through the same audited bind-once path. Pinned by "POST /onboarding with a realm and a taken hostname
   answers 409 and never binds the realm to the failed tenant".
4. Smaller hardening from the same review: the tenant-chain audit entry no longer carries the
   operator-chosen trace id (tenant admins read that chain); the onboarding-record lookup in the audit path
   takes `limit: 1` (the tenant id index is not unique).
