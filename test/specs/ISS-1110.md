# ISS-1110 (GH #2492): the ci.yml path filter must not pipe the changed list into `grep -q`

Issue record: GH #2492 (Q-1110, LOW, CI, unsafe direction). Found by REVIEWER on PR #2491. File: `.github/workflows/ci.yml`, job `changes`, step `filter`.

## Defect
The filter step runs `set -uo pipefail` and matched with `echo "$CHANGED" | grep -qE <re>`. `grep -q` exits at the first match; once the list is larger than the pipe buffer the still-writing `echo` dies of SIGPIPE, the pipeline status becomes 141, the `if` takes the else branch and the output is `false` for a list that does contain a match. The direction is unsafe (a gate is skipped). It affects all three filters (backend, frontend, mobile).

## Fix
Each filter matches with a here-string: `grep -qE <re> <<<"$CHANGED"`. No pipe, so no SIGPIPE.

## Acceptance criteria (from GH #2492)
1. No `echo | grep -q` pipe remains in the filter step (all three filters).
2. A check fails if that pattern returns.
3. Evidence on a ~20k-line changed list.

## Test cases (`test/letflow/ci_backend_path_filter_test.exs`, describe "layer 1")
- `ci.yml feeds the changed-file list to that variable via grep -qE and a here-string`: the backend line is exactly `grep -qE "$BACKEND_PATHS_RE" <<<"$CHANGED"`.
- `no filter pipes the changed list into grep -q`: no non-comment line of ci.yml matches `| grep -[..q..]`.
- `the three path filters (backend, frontend, mobile) each use a here-string`: exactly three `grep -qE ... <<<"$CHANGED"` lines.
- `the here-string form matches on a 20k-line list`: runs the here-string against a 20,001-line list whose only match is line 1, five times under `set -uo pipefail`; all five report a match.

## Evidence
Same 20,001-line list (match on line 1), `set -uo pipefail`, ten runs each, git-bash on the dev host:
- `echo "$C" | grep -qE '^(lib/|priv/)'` -> `FFFFFFFFFF` (never matches: the defect)
- `grep -qE '^(lib/|priv/)' <<<"$C"` -> `TTTTTTTTTT`

Manual mutation: re-introducing `echo "$CHANGED" | grep -qE` on the frontend filter fails 2 of 18 tests (the pipe check and the three-here-strings check); the unmutated tree passes 18/18.
