# Test Spec: GH-2638 -- DB CHECK backstop for the catalog `endpoint_url` `_sys` refusal

**Requirement:** GH #2638. Design: `lib/letflow/design/gh2638-catalog-endpoint-sys-db-guard.md` (rev 2), section 6.
Acceptance criteria (from the design table): (a) migration confirms zero matching rows first and aborts
otherwise; NOT VALID/validate semantics; a direct `Repo.insert_all` of a `_sys` URL fails on both tables;
refusal surfaces as a stable changeset error / 422, not 500; DB pattern and Elixir predicate agree (pinned
agreement table); no behaviour change for valid entries; (defence in depth) writer enumeration.
**Test tier:** unit + integration (real Postgres) + property.

Pre-fix note: the constraints, the `check_constraint` mapping and `Entry.reserved_endpoint_url_error?/1` did
not exist before this change, so "fails on the pre-fix code" is trivially true and proves nothing.
Coverage is argued per test ("what it would catch") and by mutants (below); measured counts are in the
TEST-DESIGNER handoff.

All DB files are `async: false`, `Sandbox` `:auto`, and delete every row they write in `on_exit/1`
(`gh2638-mig-`, `gh2638-par-`, `gh2638-cs-svc-` service ids). No wall-clock dependence in assertions, no
unseeded randomness (StreamData property uses the framework seed).

## Edited existing tests (done by ELIXIR-DEV in commit 7bc6cd5e, reviewed here)

`endpoint_url_reserved_test.exs` (inherited-URL test rewritten at changeset level; dispatch-resolution test
deleted) and `admin_services_reserved_endpoint_test.exs` (inherited-live-URL test removed) -- they wrote a
reserved URL raw into the catalog, which the CHECK now forbids (design R2, OQ-3).

## Mutants (for TEST-DESIGN-VALIDATOR to re-apply)

See the handoff for measured counts. Ideas: drop the VALIDATE statements; drop the pre-flight; constraint on one
table only; `~*` instead of `~`; `\s` in place of the explicit ASCII set; pattern widened (`variables\._sys` without
the `[ws]*\}\}` tail) or narrowed (`_sys\.[a-z]+`); drop `check_constraint` in one of the three changesets;
recogniser ignoring `constraint_name`; remove one of the two names from the recogniser.
