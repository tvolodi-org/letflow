# GH #2583 test spec: `managed_by` write lock enforced inside `Letflow.Entities.Records`

Design: `lib/letflow/design/gh2583-records-managed-type-guard.md` (Revisions 1 and 2), section 10.
Test ids T-01..T-29 are the design's. WF-03 run `WF03-GH2583-RECORDS-GUARD-20261015`.

## Pre-fix note and mutants

Before this change `Records` had no authority argument, no `check_record_write/3`, no
`owner_for!/1` and no `is_authority/1`: most new tests do not compile or fail with
`UndefinedFunctionError` against the pre-fix code, so "fails on the pre-fix code" is trivially
true and proves little. The behavioural pre-fix failure that does matter: on `main` (`c55baa4f5`)
`Records.create_record/2` on `org_unit` succeeds (T-01 asserts the refusal), and the deadline sweep
transitions a managed record (T-12 asserts it does not). Coverage is argued per test below and by
the mutants measured or proposed in the step-05 handoff
(`handoffs/WF03-GH2583-RECORDS-GUARD-20261015/step-05-test-designer.json`).

## Rule engine (caller scan)

Every rule in `managed_types_callers_test.exs` is a pure function over `[{path, ast}]`
(`r1_violations/1`, `r1b_violations/1`, `r2_violations/1`, `module_owner_callers/1`,
`owner_builders/1`, `r5_create_definition_sites/1`, `r5_install_callers/1`). The real-tree tests
(T-17..T-20) and the synthetic tests (T-22..T-28) call the SAME functions; synthetic tests only
change the input (`Code.string_to_quoted!/2` of snippets under fake paths). Edits to the existing
REQ-496 tests (design 7.4): `lib_files/0` became `scanned_files/0` (`lib/**/*.ex` plus
`test/support/**/*.ex`); `calls/1` gained atom receivers and runs on `normalize_pipes/1` output;
`builds_owner?/1` was extended (R4); the `create_definition/3` test filters with
`qualified?(_, :definitions)`; the `install/4` test runs on the normalised AST. Expected values are
unchanged (`[managed_types.ex, installs.ex]`, `[managed_types.ex]`, `[{solution_pack.ex, "owner"}]`,
`[installs.ex]`).
