**Issue:** `docs/issues/ISS-1061.yaml` (queue Q-1054, issue_ref ISS-1054, GH #2400).
**Design:** `handoffs/WF03-ISS1054DBGUARD-20261012/step-01-issue-fixer.json` (validated in
`step-02b-code-design-validator.json`); one paragraph in section 8 of
`lib/letflow/design/iss1042-pooled-tenant-fixture.md`.
**Code under test:** `Letflow.TenantFixture.assert_test_database!/1`, the guard call in
`start_pool!/2`, and the first statement of `Letflow.TenantFixture.Pool.init/1`
(`test/support/tenant_fixture.ex`).
**Test code:** `test/letflow/support/tenant_fixture_pool_test.exs`, describe
`"ISS-1061 database guard"` (T1..T5). Real Postgres via `Letflow.DataCase`; no mocks.
**Out of scope:** the unguarded fresh-clone / `TenantTemplate` paths.

| # | Criterion | Test |

## 2. Tests

* **T1** the guard returns `:ok` for the default and for the explicit configured name.
* **T2** a `letflow_test*` name that is not the connected database raises `ArgumentError`
  (`but the configured test database is`), the message naming both databases.
* **T3** `"letflow_dev"` is refused as `is not a letflow_test* database`, before any comparison.
* **T4** `start_pool!/2` with a fresh module and a wrong `:expected_database` raises, registers no
  worker, creates no `public.tenants` row for its unique slug, and leaves the global
  `tenant_%` schema count (which includes `tenant_template`), `public.tenants` count and the live
  pool's `pool_stats/1` unchanged.
* **T5** `GenServer.start(Letflow.TenantFixture.Pool, ...)` with a wrong `:expected_database`
  returns `{:error, {%ArgumentError{}, _}}` (log output captured).
* **T6** existing pool test file, `test/support/tenant_fixture_dispatch_test.exs` and every
  `start_pool!` adopter file run unchanged and green.
